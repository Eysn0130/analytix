## Why

Analytix released fabricated high-risk case facts after its Go runtime first recognized that the current case source was unavailable, then injected a contradictory final-recovery prompt and accepted model-simulated evidence. Prompt guidance and structured output alone cannot close this control gap: the host must make unsupported case facts mechanically unpublishable across every terminal path, case switch, restart, report fallback, UI projection, and provider family.

The incident response subsequently over-corrected toward count-only case
plumbing and an expanding family of authority, receipt, registry, CAS, and
staging versions before proving the ordinary packaged Agent experience.
Analytix remains a general Agent product first. Case evidence is an
on-demand professional capability, and missing case bindings, funds data, or
dataset authority must disable only case-fact work.

“General” and “case” describe acceptance scenarios, not two Agents, modes,
threads, or global tool configurations. Analytix has one Agent and one
continuation model. General capabilities are the permanent base; case funds
capabilities are added dynamically to the current turn and individual
data/effect calls only while the exact case, snapshot, epoch, and grant remain
current.
