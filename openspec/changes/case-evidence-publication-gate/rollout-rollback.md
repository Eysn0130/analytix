# Rollout And Rollback

Status: Normative release attachment for this change.

## Rollout Stages

### P0 containment

Ship only after the incident path, Agent-mode tool allowlist, draft/reasoning leakage, `active` factual caches, unsafe report fallback, zero-write behavior, citation defaults, and approval-never report bypass are fixed with all P0 tests green. High-risk publication remains disabled/boundary-only where the P1 gate is not ready.

### P1 evidence kernel

Enable executable case analysis only after the shared Context Epoch, V2 security context, strict binding observer, independent monotonic risk/evidence authority witness, live source probe, grant, outcome, receipt registry, claim verifier, every-terminal finalizer, pending-gate revalidation, and persistence/restart behavior pass without skips. Until then the host publishes only a fixed boundary and invokes no case effects.

P1 additionally requires the exact-root `PublicToolResultProjectionV1` at every Go/TypeScript/Electron/renderer boundary, a journaled migration that removes legacy raw tool results from ordinary durable stores, a separate closed durable projection for tool-call arguments, and owner/use/effect-lease authority for tool-originated media. Read-time `legacy_output_withheld` containment is necessary incident protection but is not migration completion. Any raw-result sentinel, binding mismatch, unknown/remote code, inline media/path promotion, stale media lease, upload/owner crash ambiguity, or red/ skipped cross-layer test keeps case execution boundary-only.

Authority Advance Journal V2 is not enabled merely because its domain records or immutable store compile. Activation additionally requires the journaled V1 terminal fixed point, exclusive V1-writer shutdown/V2-writer activation, fresh live witness-tail binding, unresolved-intent Observe plus complete committed-range reconciliation, startup inventory/restart recovery, and current-anchor projection readback. Any missing migration marker, V1 in-flight writer, ambiguous settlement, inventory bound breach, unsafe ACL/DACL/ADS/link/FileID state, or unexecuted platform security test keeps that namespace boundary-only.

Semantic persistence V4 is likewise not release-ready merely because Unix migration and Windows cross-compilation pass. Release permits only the narrowly specified exact-empty staged-directory create-residue pass before the journal; authenticated journal recovery must still precede canonical orphan-topology cleanup, globally preflighted store-owned CAS recovery, and the first baseline. Release additionally requires bounded/cancellable startup on production call paths, removal of the transitional full private/attachment planning clone, authenticated retirement migration/consumption across every crash cut, and real Windows NTFS/ReFS execution. An authenticated legacy artifact that needs unavailable full identity blocks startup without cleanup or downgrade. A pre-activation signal must produce no listener/readiness publication.

Attachment owner integrity is also not release closure by itself. Ownerless/global/workspace-only legacy records remain quarantined, and ordinary UI responses must stay on the safe metadata projection without raw blob hashes, caller OS paths, extracted text, fallback bytes, or owner material. Case attachment execution remains fail-closed until the exact-turn `AttachmentUseReceiptV1`, private-CAS recovery, context-effect lease ordering, case-switch race tests, attachment-id preview/save/open host actions, and desktop contract migration are complete. Rollback may disable attachment execution or require re-upload; it may not restore blob-hash global ids, public source paths, filename merging with generated artifacts, merged scope lists, silent missing-attachment omission, or unverified provider payloads.

### P2 funds/data/report

Enable verified funds answers and formal reports only for migrated immutable snapshots, strict plugin contracts, source-capability claims, masked projections, and publication receipts. Other sources remain boundary-only.

### P4 production closure

Complete provider families, real desktop bridge/UI, cold/disconnected/spoofed/restart cases, current-host packaging, supported external platform evidence, safe observability, release metrics, and operator review.

## Production Defaults

- Final evidence and report gates are always on.
- There is no ordinary user disable switch.
- Missing/misconfigured components produce boundary-only answers.
- Strict provider schemas assist but never replace the local gate.
- Ordinary non-case functionality uses its ordinary Core execution policy and
  grants. Optional case/funds/registry/witness failure does not become a startup
  prerequisite for independent ordinary work; see accepted `Case Evidence Is
  Optional To General Agent Work`. An existing protected case lineage must not
  be relabeled general to bypass its risk or witness requirements. Genuine Core
  integrity or ordinary-work dependency failure still fails closed.

## Rollback

1. Prefer a forward fix while the gate keeps high-risk publication blocked.
2. A binary rollback is allowed only to a gate-preserving version proved by a rollback scenario.
3. If no safe prior version exists, disable verified case answers/reports and render only fixed source/evidence boundaries.
4. Never select the retired TypeScript runtime, re-enable free-form Markdown case finals, trust legacy citations, restore unsafe report fallback, or reuse legacy factual caches.
5. Preserve receipt/publication audit records and immutable raw snapshots; rollback must not rewrite history to hide failed publication attempts.

## Platform Truth

The current macOS host must run the real app and relevant macOS package path. Windows and Linux pass only through supported CI or approved hosts that actually execute their build/package/startup/gate scenarios. Missing signing credentials, provider keys, MCP sources, or platform hosts are recorded as external unverified rows and prevent claims limited by those rows.
