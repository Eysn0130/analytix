## Context

The production path is Electron/React/TypeScript at the desktop boundary and Go in `packages/runtime-go` for the only production agent core. The incident occurred inside the Go loop: a current-case funds policy correctly declared the source unavailable, but a later final-recovery prompt told the model to continue the case analysis. Provider text and reasoning were already emitted as SSE deltas, intermediate assistant drafts could be persisted as completed items, and the final response had no host-owned receipt/claim/publication gate. The model therefore simulated a tool and invented company relationships, amounts, accounts, device identifiers, bid prices, and legal conclusions without a successful funds-tool result.

The accepted `context-epoch` capability from archived `context-epoch-foundation` defines and implements the generic thread-scoped source registry, accepted epoch snapshot, safe-boundary reconcile, prefix reason, compaction, and restart semantics. This change consumes that implementation and extends the same epoch with frozen case binding and dataset identity. It must not add a parallel epoch counter, registry, or persistence record.

The current funds plugin contains useful semantic tools and report/evidence helpers, but its outputs, cache keys, fallbacks, citation assignments, source semantics, PII handling, and publication lifecycle are not yet sufficient to establish a high-risk fact. Analytix's own accepted contracts, production paths, and fresh public-seam evidence are the only baseline for determining whether those mechanisms are implemented.

The corrected as-built baseline is sharper: the packaged production MCP
closure advertises only `count_case_rows`, while useful DuckDB semantics live
outside that closure; Electron packaged startup still has unconditional funds
materialization and controlled-artifact dependencies; and existing native
stats money uses floating-point representations that are not receipt-eligible.
These are implementation gaps, not reasons to add another authority family.

Desktop Write currently creates DOCX by rendering renderer-supplied Markdown
to HTML and passing that HTML to `html-to-docx@1.8.0`. Its production graph
retains an archived, unpatched `image-size` parser and an affected `nanoid`, and
the focused tests inspect HTML rather than the produced OOXML package. The
renderer also supplies `workspaceRoot`, and the `write:export` handler does not
yet reject a non-current frame. This is not sufficient evidence for a
Host-owned commercial DOCX capability.

## Goals / Non-Goals

**Goals:**

- Preserve exactly one Analytix Agent whose coding, file, shell, Git,
  test/build, research, writing, Plan, Todo, MCP, Skills, thread, subagent,
  compaction, recovery, and shutdown capabilities form the permanent base and
  do not depend on case evidence.
- Keep `A0` (packaged general-Agent/provider live certification) and `B1`
  (Funds Plugin vertical implementation and evidence) as independent tracks.
  Provider contract failure or missing fresh credentials may block A0 live
  certification without stopping deterministic B1 implementation,
  verification, or focused integration.
- Add case funds capabilities to that same Agent at the current turn and
  individual data/effect call only; permit ordinary and case work to
  interleave in one request and one durable thread without a global mode,
  mutually exclusive catalog, or Agent replacement.
- Prove Milestone A through one fresh formal packaged Electron workflow in an
  isolated non-case repository using the production Go backend and real public
  seams across edit, test, child work, compaction, exit, relaunch, and thread
  recovery.
- Make a high-risk case fact mechanically unpublishable without a current,
  host-issued, registry-backed receipt bound to the same thread, turn, case,
  epoch, and dataset snapshot.
- Reuse the completed TSCV2, DSV2, host evidence, EvidenceReceipt, Final Gate,
  and controlled-artifact foundations instead of expanding parallel authority
  versions.
- Prove Milestone B with a packaged, valuable, multi-turn DuckDB funds
  investigation for an account/entity and time range, returning inflow,
  outflow, signed net, transaction count, supporting evidence rows, stable
  entity continuity, snapshot evolution, receipt/claim/Final Gate acceptance,
  the four closed typed local data surfaces, stable authority references plus
  short model aliases, independent-thread same-case rehydration, and
  Final-Gate-gated source-exact `AcceptedSlotDisplay`, with source-exact values
  in the current local typed UI by default and a user-selectable masked display
  mode.
- Route every turn-terminal candidate capable of producing an accepted
  assistant event or case-factual slot through one host-owned final evidence
  gate. Resume/restart/recovery are continuity inputs, background completion
  is typed delivery to an already-terminal parent, and only a new continuation
  turn candidate passes the gate.
- Preserve useful partial, no-hit, unavailable, missing-evidence, and
  general-guidance responses without upgrading them into whole-case facts.
- Prevent provider reasoning, raw database paths, arbitrary SQL authority,
  complete account/card values, and unaccepted case drafts from entering
  provider/model context, MCP/public tool results, generic HTTP/SSE or bridge
  events, free-form renderer/durable state, search, logs, telemetry, crash
  reports, compaction prose, generic report state, unbound report bytes, or
  automatic/unrestricted exports.
- Permit source-exact local display only through the closed
  `typed-local-data-surface/v1` family: `ImportMappingPreview`,
  `CleaningDiffPreview`, `DirectSourcePreview`, and `AcceptedSlotDisplay`.
  Bind each variant to its exact staged generation or immutable input/output/
  retained snapshot lineage, the installation-local session, current
  main-frame renderer principal, case, bounded row window, and requested
  fields; never deliver the mapping table, key material, DuckDB locator/
  descriptor, unrelated fields, raw evidence, or cross-case identity links.
- Give the model only task-necessary verified semantics—short typed
  case-scoped aliases resolved by the host to stable authority references,
  typed attributes and relationships, exact minor-unit
  amounts, direction, date range, coverage/currentness, ClaimRecord/
  EvidenceReceipt references, counterevidence, and unresolved questions—without
  giving it source-exact identifiers.
- Preserve the same case entity identity across turns, tools, Todos,
  subagents, compaction, restart, resume, permitted forks, and an explicitly
  case-bound independent new thread while keeping
  entity identity separate from snapshot/evidence/claim version identity and
  isolated from every other case by default.
- Ship ordinary DOCX from Desktop Write through a current-main-frame,
  Main-derived workspace, host save-dialog, masked local projection, and pure
  document AST to OOXML pipeline with no Agent turn, Provider, MCP, funds
  plugin, arbitrary HTML converter, or native child process.

**Non-Goals:**

- Count-only `count_case_rows` is a plumbing canary, not funds-product
  delivery or Milestone B acceptance.
- Broad formal report expansion, unrestricted external effects, and unrun
  target platforms are independent
  later/external-condition rows and do not block Milestone A or standard local
  source-exact case analysis. Existing controlled-artifact or one-use
  trusted-sink paths remain optional for formal export/external sharing or a
  high-security viewer; they are not standard local-display prerequisites.
- Apart from the bounded ordinary Desktop Write DOCX slice, this train does
  not add or expand copy, export, share, upload, Connector, third-party legal
  approval, controlled-viewer, marketplace, or other external-effect features.
  It does not make source-exact case export a B1 requirement.
- No new authority, receipt, registry, CAS, or staging version without a fresh
  public-seam failure that proves the accepted topology cannot enforce a named
  invariant and a separately accepted migration/rollback design.
- No prompt-only, regex-only, temperature-only, second-model-review, or
  model-reported safety field is an authority boundary.
- No TypeScript production agent loop, renderer-visible runtime switcher,
  second agent runtime, `caseMode`, `generalMode`, whole-thread case switch,
  or ordinary user switch for disabling case publication gates.
- No new Rust Agent Runtime. Existing packaged Rust data-plane components may
  be reused for their bounded typed DuckDB operations.
- No publication of user incident inputs, local case data, credentials,
  temporary evidence, or generated package artifacts as repository source.

## Decisions

### Decision 0: One Agent with an additive per-call case capability

Production composition has one Agent, one thread model, and one ordinary tool
base:

```text
user request / durable thread
-> ordinary workspace + execution policy
-> general tools / MCP / Skills / Plan / Todo / subagent remain available
-> branch A, explicit Direct Source Preview:
   renderer supplies typed view/fields/row window/display mode only
   -> Main derives canonical workspace from current settings/main-frame authority
   -> current local session + main-frame principal + host-resolved active case/snapshot
   -> trusted host/data-plane read of requested rows/fields only
   -> ephemeral typed local UI projection (full by default or masked)
   -> zero provider/MCP/EvidenceReceipt/ClaimRecord/Final Gate calls
-> branch B, Agent case-factual answer:
   each requested protected-data call independently checks
   current TSCV2 + DSV2 + host evidence + exact grant
   -> verified case outcome -> EvidenceReceipt -> ClaimRecord -> Final Gate
   -> PII-free accepted envelope with typed entity/claim slots
   -> AcceptedSlotDisplay resolves referenced fields in Go after the gate
   -> ephemeral typed local UI projection (full by default or masked)
-> continue ordinary or case work in the same Agent and thread
```

“General project” and “case project” are acceptance scenarios, not modes.
There is no `generalMode`, `caseMode`, one-shot analysis Agent, whole-thread
tool replacement, or global case/funds enable switch. The host composes the
case tool into the current provider catalog only while its exact authority is
current, and revalidates that authority again at the concrete data access and
effect. Ordinary tools remain present under their ordinary grants before,
during, and after a case call.

Case/funds dependencies are lazy or degradable. Missing plugin materialization,
case binding, dataset selection, or evidence witness removes only the affected
case-data call or case-fact acceptance. Missing report, controlled-artifact,
PII-grant, or external trusted-sink capability removes only the corresponding
external effect or optional high-security view; it does not disable standard
typed local display. No optional case dependency is an unconditional packaged
startup dependency or may cancel already-authorized ordinary work in the same
or another turn. A mixed request may therefore return an ordinary-work success
and a typed case boundary in one accepted terminal result.

The authority topology is frozen for first-stage delivery. Existing
uncomposed V3/V4 or experimental objects remain preserved implementation
material but acquire no production authority and block neither lane. A new
version requires a reproducible public-seam failure, an accepted invariant that
cannot otherwise be enforced, named owner/caller/consumer/failure paths, data
compatibility and rollback, and packaged end-to-end proof.

Alternative considered: implement two product lanes, a startup
`general-only` fallback, or make case authority readiness the global runtime
health gate. Rejected because each creates a mode boundary around the Agent
instead of the protected data/effect, risks silently dropping ordinary tools,
and makes an optional professional capability the product's boot dependency.

### Decision 0a: Ordinary history is rebuilt from typed committed results

The ordinary provider lane never derives reusable assistant history by
filtering a case transcript or parsing an accepted case rendering. The host
extracts only `provider_ordinary_only` `ResultSlotV1` values from two existing
terminal authorities: the exact general terminal CAS/outbox and the committed
case accepted-final plus its primary-CAS raw-turn digest. Host-fixed boundary
text, case answer prose, tool drafts, mixed current prompts, internal entity
references, and untyped legacy assistant text are not history inputs.

The runtime keeps this typed history as a separate ordinary-lane baseline.
An exact ordinary turn or signed ordinary steering transition starts from the
base system prompt plus that baseline; a protected authority failure cannot
turn the current unpartitioned protected transcript into ordinary history by
sanitizing it after the fact. If the existing resolver/CAS or durable turn
inventory cannot prove a slot, the prior ordinary history is empty and there
is no raw fallback. This withholds context only: it does not zero the ordinary
catalog, block the current ordinary request, or introduce another authority,
receipt, registry, CAS, staging version, Agent, or mode.

### Decision 1: One host-owned case acceptance pipeline

The only case-fact publication path is:

```text
Request
-> host case-binding observation
-> existing TSCV2 host-derived risk/publication policy
-> existing immutable TurnSecurityContextV2
-> existing DatasetSnapshotAuthorityV2 selection
-> current-run source live probe
-> ExecutionGrant
-> verified ToolOutcome
-> host-issued EvidenceReceipt
-> normalized ClaimRecord
-> Final Evidence Gate
-> PII-free deterministic accepted envelope with typed display slots
-> generic accepted event / history / HTTP/SSE remains PII-free
-> Go host resolves only referenced source fields
-> Electron Main delivers AcceptedSlotDisplay to the current typed local UI
```

Every case failure branch produces a typed blocker or boundary-only envelope
and bypasses model case-fact completion. A provider response is proposal
material, never the publication record. `AcceptedSlotDisplay` is a local
projection of already accepted typed slots, not a second publication authority;
`displayMode=full|masked` changes only that final projection. Formal reports,
external effects, controlled artifacts, and optional high-security viewers are
independent consumers and are not required for the standard local answer.

Direct Source Preview is deliberately outside this Agent case-fact pipeline.
It performs no provider, MCP, EvidenceReceipt, ClaimRecord, or Final Gate call;
trusted host/data-plane code reads only the exact rows and fields requested
from the active immutable snapshot and returns them through the dedicated local
typed sink. Preview data cannot become a ClaimRecord or provider continuation
merely because the user viewed it.

Only the protected-data access, case-fact claim, and case publication portions
of a request traverse this pipeline. Ordinary file/code/shell/Todo/subagent
portions use the established Agent loop and ordinary policy in the same turn
and thread. If the case portion is missing authority, the host accepts the
ordinary result and attaches a typed case boundary rather than restarting the
Agent, zeroing the catalog, or failing the entire mixed request.

Alternative considered: keep free-form model finals and add citations or an
LLM reviewer. Rejected because a model can forge identifiers, mismatch
citations, follow hostile recovery text, or agree with another model without a
source execution.

### Decision 2: Extend the existing Context Epoch foundation

`internal/domain/contextepoch` owns one generic Context Epoch identifier and accepted snapshot model. The accepted `context-epoch` capability owns generic source registry/reconcile/prefix behavior under `internal/app/contextepoch`. This change adds case-specific source descriptors and freezes their accepted values in `TurnSecurityContext`:

```text
threadId, turnId, workspaceRealPath, tenantId, userId, caseId,
caseBindingHash, datasetSnapshotId, sourceManifestHash, contextEpoch,
issuedAt, contextDigest
```

The context digest is SHA-256 over canonical versioned fields. Case/workspace/binding/snapshot changes reconcile and bump that same epoch before the next turn. Mid-turn changes cancel or invalidate old work. Pending approvals, user input, task jobs, MCP calls, caches, provider continuation, compaction, report staging, and persistence carry the digest and epoch.

If the foundation remains unimplemented when P1 begins, its domain/persistence/safe-boundary tasks are implemented first in the shared types and recorded against both changes. No second counter or compatibility alias is allowed.

Alternative considered: a funds-plugin-only `caseEpoch`. Rejected because it would not protect provider history, pending gates, background jobs, renderer persistence, or non-funds evidence sources.

### Decision 2a: Defer the independent risk witness unless a public seam proves it necessary

`ThreadRiskAuthorityIndexV1` and its independent monotonic witness are a
historical stronger proposal, not a Milestone A or B dependency. First-stage
work reuses the accepted TSCV2, DSV2, execution/evidence/final authorities and
their existing recovery contracts. Missing or invalid case authority blocks
only the affected protected data call or case-fact publication; it never gates
ordinary Agent startup or ordinary tools. The witness proposal may be
re-admitted only when a fresh formal packaged rollback seam proves that the
existing structures cannot enforce an accepted invariant, followed by an
updated compatibility, rollback, and verification design. Existing partial
implementation is preserved but does not justify composition or delivery.

> **Deferred, non-normative rationale:** the next three paragraphs preserve the
> original witness proposal for later evaluation. They describe what the
> proposal would require if a proving packaged failure re-admits it; they do
> not override the first-stage freeze or create an A/B dependency.

If re-admitted, the proposal would address the fact that an installation-signed policy, content-addressed record, local head file, or maximum generation proves integrity of the bytes that remain but not that a newer state was deleted or a complete older filesystem snapshot was restored. It would bind executable V2 contexts to an exact current `ThreadRiskAuthorityIndexV1` generation/digest and a witness-signed checkpoint/receipt obtained through exact compare-and-swap. The proposed witness would store only installation/enrollment identifiers, namespace, generation, state digests, mutation id, challenge nonce, and signatures; it would receive no thread, workspace, case, prompt, account, evidence, or other PII.

Under that deferred proposal, policy and index records would remain immutable local CAS material, while the local head would be only a projection of witness state. Protected high-risk effect/publication boundaries would revalidate the witness; an invalid or unavailable witness would block only the protected case effect, never startup or unrelated ordinary provider, MCP, file, shell, Todo, subagent, compaction, or recovery work.

Alternative considered: treat Ed25519 signatures, Keychain/DPAPI/libsecret storage, or a signed local generation file as monotonic. Rejected because authenticity and secret storage do not prove latest-state freshness across complete local rollback.

### Decision 2b: Case-scoped entity identity is stable and separate from evidence versions

Identity has three representations with no implicit conversion:

1. `SourceExactIdentityV1` is the original value plus source/snapshot/row/field
   lineage. It is visible only to trusted DuckDB/private computation and an
   exactly bound typed local surface.
2. `AuthorityEntityRefV1` is the existing installation-keyed, entity-type and
   case-domain-separated, collision-resistant reference. It is the durable
   host/evidence binding and may be long; it is not provider prose or a user
   label.
3. `ModelEntityAliasV1` is a short typed selector derived from the existing
   private binding's `StableOrdinal`, initially `acct:<positive-decimal>` and
   `card:<positive-decimal>` because only those entity types are implemented.
   It has no authority by itself. Before any tool use, the Go host resolves it
   under the exact TSCV2/DSV2 frozen case to one AuthorityEntityRef and current
   binding. Future `person:`, `org:`, `phone:`, `device:`, or `merchant:`
   prefixes require separately implemented canonicalizer and correction
   contracts; their names here are target vocabulary, not as-built support.

The host reuses the existing caseentity binding store for alias resolution and
does not add a registry, CAS, database table, global token, or provider-visible
reverse map. The same governed identity in one authorized case retains its
authority reference and alias ordinal across turns, funds calls, Todo,
subagent, compaction, restart, resume, permitted forks, and an explicitly
case-bound independent new thread. Any collision, missing ordinal, duplicate
alias, ambiguous binding, stale case/snapshot, or unsupported entity type fails
closed. Sequential ordinals reveal only bounded case inventory/order and are
therefore admitted only as task-selected aliases, never as counts, global
identities, or evidence.

Entity identity and factual version identity are independent:

```text
AuthorityEntityRefV1
  = continuity of the same governed entity inside one case

ModelEntityAliasV1
  = short selector for the current frozen case; no authority/currentness

snapshot/evidence/claim bindings
  = which immutable data version supports a particular fact
```

A new DatasetSnapshot may preserve a verified authority reference and alias
ordinal while every
fact, relation, amount, coverage statement, receipt, and claim from the old
snapshot remains bound to the old version and is projected as
`historical`, `stale`, or `superseded` unless independently supported by the
new snapshot. A case A -> case B switch advances the shared Context Epoch and
changes the reference scope. Identical raw values in different cases do not
produce a model-visible cross-case link. A cross-case relationship may be
assembled only after the user explicitly selects the exact case set and the
host binds each independent case authority, allowed entities, purpose, and
audit use; it reuses the existing case/evidence chain rather than creating a
global identity registry. Legal-characterization claims may still require
their configured lawful-purpose and human-review rules, but those rules are
not prerequisites for ordinary local display.

That relationship never merges case owners. Across turn, compaction, restart,
resume, and permitted fork, each case keeps an independent reference namespace,
current snapshot/currentness, claims, and receipts. The host revalidates the
complete joint scope before every use; revoking one case removes the relation
without leaking or destroying state that remains authorized in another case.

Merge, split, and correction are explicit immutable caseentity events. A merge
chooses one survivor and records aliases as retired redirects only inside the
same private owner; a split creates new authority references/ordinals and
marks prior facts ambiguous until re-resolved; correction never rewrites old
evidence or reuses an ordinal for another entity. Canonicalizer or identity-key
rotation uses versioned re-derivation with an old-to-new private transition,
fails closed on incomplete migration, and does not expose cross-case linkage.

The private source/canonical/authority/ordinal binding and exact raw user-input
audit record live only in the already accepted host-private persistence
topology. The canonical value is a derivation input and MUST NOT substitute for
source-exact typed display; `AcceptedSlotDisplay` must read the original
retained snapshot row/field lineage.
Provider/model context, provider continuation/history, subagents, MCP public
results, ordinary tool projections, generic HTTP/SSE or bridge events,
free-form renderer/durable state, search, logs, telemetry, crash reports, and
compaction prose receive neither AuthorityEntityRef, reverse mapping, nor
source-exact values. They receive only task-selected ModelEntityAlias values
and closed semantic/evidence projections.
The dedicated local typed sink may receive only the requested source fields,
never the mapping table, key material, DuckDB locator/descriptor, unrelated
fields, raw evidence blobs, or cross-case reverse links.

Alternative considered: use a suffix, bare hash, deterministic ciphertext,
format-preserving encryption, database id, a model-assigned label, or an
installation-global token as identity. Rejected because they collide or expose
equality/format/order, drift after restart, create cross-case linkage, or make
the model-visible value an authority. A StableOrdinal-derived alias is accepted
only because the host persists and resolves it through the existing private
caseentity authority.

### Decision 3: Host-issued grants and receipts are capabilities, not strings

An `ExecutionGrant` is minted only after the current run verifies source/server identity, catalog freshness, schema hash, case-bound health, scope, approval, expiry, and read-only/write posture. Provider-originated calls must match the exact grant. Unknown tools, unadvertised tools, unknown schemas, wrong servers, expired grants, stale context, and scope mismatches are rejected before execution in every mode.

An external result cannot issue its own authoritative receipt. The host validates transport/semantic status, hashes canonical arguments and result bytes, verifies server connection identity, checks case/epoch/snapshot binding, and inserts a versioned `EvidenceReceipt` into the durable turn registry. Membership plus registry integrity proof is required; a non-empty id is not evidence.

Alternative considered: trust `caseId`, `safeToAnswer`, `supportStatus`, `sourceId`, identity, or coverage returned by MCP/model output. Rejected as untrusted boundary data.

### Decision 4: Tool outcome separates transport and meaning

`ToolOutcome` keeps `transportStatus`, `semanticStatus`, `safeToAnswer`, `isError`, blocker, partial coverage, data, and candidate receipt material distinct. HTTP/JSON-RPC success with MCP `isError`, semantic failure, unsafe answer, partial result, invalid schema, or missing receipt is not a successful evidence outcome. MCP adapters preserve `_meta`, error codes, and coverage rather than flattening them into text.

### Decision 5: Claim verification is deterministic and source-capability-aware

Provider or plugin output is normalized into typed `ClaimRecord` proposals. The verifier checks exact normalized fields for subject, account, amount, count, direction, date/time window, relation, quote, device identifier, currency, and scope. It also checks that the cited source type is authorized for the claim type. Unknown citations, bulk citation assignment, semantic mismatches, counterevidence, incomplete pagination, partial coverage, and cross-context receipts reject or narrow the claim.

`allowedWording` and `prohibitedUpgrades` constrain deterministic rendering. Empty results become a verified no-hit only when a receipt proves the queried scope and completeness; they never imply zero, nonexistence, no relationship, or no anomaly outside that scope.

Alternative considered: citation-presence checks. Rejected because a valid receipt for another entity, field, period, direction, or claim does not support the proposed fact.

### Decision 5a: The host compiles necessary case semantics without source-exact PII

Before any provider request, the host resolves the current authorized case and
snapshot, scans typed user-input fields for complete protected identifiers,
and privately resolves each value to its AuthorityEntityRef, then emits only
the current frozen case's short typed ModelEntityAlias. The provider payload
contains that alias and a typed redacted user message, never the source-exact
span or AuthorityEntityRef. If a value cannot be resolved or authority is
missing, the exact value is still withheld, the affected case request becomes
boundary-only, and independent ordinary portions continue.

For each case continuation the host assembles only task-relevant, verified,
structured semantics from existing evidence/claim/private-state owners:

- short typed model alias, entity type, account type, task-necessary
  institution semantics, currency,
  and host-derived non-sensitive attributes;
- amounts, direction, balances, time, frequency, transaction counts,
  counterparties, permitted relationships, and funds paths;
- query filters, data coverage, missing ranges, lineage, derivation method,
  and confidence/support state;
- current and historical snapshot identity, fact currentness, changes,
  counterevidence, rejected hypotheses, unresolved questions, and next steps;
- EvidenceReceipt/ClaimRecord references and the exact scope each supports.

Exact matching, joins, aggregation, precise money, and deterministic feature
derivation remain in the trusted DuckDB/data-tool boundary. The model receives
enough semantics to select tools, form and test hypotheses, compare results,
and explain findings, but it never derives bank/card/region/age attributes
from complete identifiers or performs database arithmetic that the trusted
tool can compute exactly.

Provider output names typed claims, model aliases, evidence references,
and answer slots. It cannot place a source-exact identifier in a generic
string field and cannot authorize final value substitution. Internal entity
references are analysis protocol values, not user-visible product language:
after Final Gate accepts the exact case/snapshot/epoch/claim/receipt bindings,
the Go host resolves only the fields named by those typed slots and Electron
Main delivers an `AcceptedSlotDisplay` projection to the current main-frame
renderer. The active-case local UI defaults to `full`; `masked` is a user
privacy mode. Neither display mode changes the provider body, ClaimRecord,
EvidenceReceipt, evidence digest, or Final Gate result.

Exact financial semantics are not generalized for privacy. Amount, balance,
signed net, currency, scale, direction, count, coverage, missing/null/invalid,
bounded query predicates, evidence/currentness, and graph direction/topology
remain closed exact types and are computed in trusted DuckDB/Funds code with
integer minor units or exact decimals, never binary float. Exact timestamps,
merchant/institution/branch, and geography are admitted only when the bounded
tool needs them and their combination passes the task-specific re-identification
budget; otherwise the host uses a declared range/category or withholds them.

Alternative considered: send star-masked prose or complete user-entered
identifiers to the model and scrub the final string with regular expressions.
Rejected because masks can merge entities, provider history already leaked the
input, and string replacement cannot prove field/claim/evidence binding.

### Decision 5b: Image privacy is enforced before every provider effect

An original user or tool image is uninspectable provider input until a
host-owned trusted local component has inspected it and produced a
deterministic privacy-safe textual observation or image derivative. The
source bytes, source-exact image URL, data URL, and any uninspectable remote
reference remain in the existing private attachment/tool-result ownership
topology. Neither a text-only primary model's Vision Bridge nor a
native-vision primary model receives that original input.

The same provider privacy projection is mandatory at both primary and bridge
dispatch. It accepts only the trusted local projection and rejects raw
`Data`, `ImageURL`, `data_base64`, or equivalent parts before the provider is
called. The local projection must remove complete protected identifiers and
bind its output to the exact owned attachment or tool-result effect; it is not
an authority, receipt, or evidence source and cannot make an image-derived
case claim factual by itself.

Until a production trusted local image inspector/projector is composed, the
image observation is explicitly unavailable and all image-bearing provider
dispatch remains at zero calls. This failure is scoped to the concrete image
effect: text, code, file, shell, Todo, subagent, ordinary MCP, and other
already-authorized work in the same Agent/request continue. Renderer
capability reporting permits image selection only when this local projection
and a compatible downstream model path are both ready.

Existing saved attachments remain private and are not migrated into provider
history or replayed automatically. Rollback disables the provider image
effect while retaining attachment ownership/recovery and all non-image Agent
capabilities.

Alternative considered: send the raw image to a separate Vision Bridge first
and redact only its textual response. Rejected because the bridge is still a
provider/model context and the complete PII has already crossed the forbidden
boundary before response filtering can run.

### Decision 6: Final answers are a closed discriminated union

The gate produces exactly one of:

- `EvidenceBackedAnswer`
- `PartialEvidenceAnswer`
- `VerifiedNoHitAnswer`
- `SourceUnavailableAnswer`
- `NeedsEvidenceAnswer`
- `GeneralGuidanceAnswer`

High-risk factual slots appear only in the first three and only from verified
claim records. The generic union contains typed entity/claim/source-field
bindings and PII-free deterministic prose, never reconstructed source-exact
values. `PartialEvidenceAnswer` cannot render whole-case wording.
`SourceUnavailableAnswer` and `NeedsEvidenceAnswer` contain only checked scope,
blocker, missing evidence, and acquisition steps. `GeneralGuidanceAnswer` is
claim-free and cannot reference current-case entities as facts. Direct Source
Preview is a separate local data-view operation and does not enter this union
or Final Gate.

Host templates, not a second model call, render accepted case answers. Provider strict schema is a proposal-shape aid only.

### Decision 7: High-risk streams are staged, not published

For a routed high-risk case turn, raw provider text is held in a bounded in-memory proposal buffer. It is not emitted as assistant text, written as a completed item, or added to provider-visible durable history until the final gate accepts an envelope. Host-originated progress events may stream counts/status without case facts. Tool calls remain visible only after grant validation and with sanitized arguments/status.

Raw tool results and tool-originated media follow the same private/public
separation. Even the immediate provider continuation receives only the
host-compiled structured semantic projection containing stable entity
references, verified attributes/relations, exact analytical values, coverage,
and evidence references needed for the current attempt; complete identifiers,
raw database rows, paths, and reverse mappings never enter a provider payload.
That semantic projection is usable only inside the current attempt with a
valid context-effect lease. Persistence, restart replay, generic HTTP/SSE,
free-form renderer state, history, compaction prose, and automatic export
receive only the exact closed `PublicToolResultProjectionV1` plus separately
host-retrievable typed case continuation references; they cannot recover raw
bytes from either. Arbitrary `attachments`, `files`, `generatedFiles`,
`sources`, `citations`, `dataUrl`, URL, command, path, summary, or diagnostics
fields are not public artifact or citation authority. Tool-call arguments are
a separate untrusted input surface and require their own closed durable
projection; withholding the result does not authorize replaying the call
payload.

Case-source settlement keeps the authority and public shapes deliberately
separate. The first settlement validates the full process-local `ToolOutcome`
against tool/call, context/epoch/grant, case/snapshot/server, transport,
semantic, error, safety, receipt, and evidence bindings. Only after that check
may the canonical private durable tool-result root retain the outer
tool/call/context-digest/epoch/grant tuple plus one strict host-only binding
proof over a closed version/purpose, that tuple, projection kind/status/code,
and `isError`.
The proof contains no `ToolOutcome`, case/source value, PII, path, reverse map,
raw tool body, or provider text. On every public read, the host recomputes this
proof from the still-private durable root; missing, duplicate, open, unknown,
malformed, or rebound proof/tuple/lifecycle state becomes
`legacy_output_withheld`. `PublicToolResultProjectionV1` remains metadata-only
and serializes neither the proof nor `CaseOutcome`, `contextDigest`,
`contextEpoch`, `executionGrantId`, `datasetSnapshotId`, or any settlement
authority.

After Final Gate, an `AcceptedSlotDisplay` request causes the Go host to resolve
only the referenced source fields and consume its private value carrier exactly
once for the current renderer session. Electron Main forwards the short-lived
typed payload only to the requesting current main-frame principal. Generic
accepted-final text, SSE, history, preload/IPC events, renderer stores, search,
logs, telemetry, crash reports, and compaction prose remain PII-free. A Direct
Source Preview uses the same allowlisted local sink but reads requested fields
directly from the active snapshot and never creates provider or evidence-gate
state.

Attachment upload does not span ordinary files and private owner CAS through two independent HTTP callbacks. One Go application use case owns a private-CAS intent, durable file stage, live binding recheck, atomic open-intent owner commit, and terminal private disposition. Startup inventories every legacy owner, intent, disposition, metadata file, and content file before applying a recovery plan. Exact complete/current open intents may converge to committed exactly once; owner-before-response converges to committed; every incomplete, corrupt, stale, unattributed, or explicitly rejected state remains without owner authority. The existing `SecurePrivateCAS` implementation and persistence lease remain the only private transaction substrate.

Reasoning chunks are consumed only as ephemeral provider protocol state where required for the current request/tool continuation. They are never sent to the event recorder, persisted in messages/history, placed in tool-call items, copied into compaction, or rendered/exported. Provider reasoning signatures may remain ephemeral for a single protocol continuation but are discarded before durability.

Alternative considered: stream and later delete rejected drafts. Rejected because SSE clients, logs, screenshots, and append-only histories cannot be reliably recalled.

### Decision 7a: Automatic compaction preserves one typed Agent continuation

Before admitting any new turn, the Go host estimates the exact bounded request
context against the selected provider model's context window. At the 75% soft
threshold it may perform at most one deterministic automatic compaction; at
the 85% hard threshold after compaction it returns a fixed host blocker with
zero provider calls. Unknown model windows use the declared conservative
fallback rather than zero.

The compaction carries a digest-bound continuation containing the active Goal,
unfinished Todos, latest user constraints, compaction ancestry, stable
case-scoped entity references, current verified claims, relevant historical
comparison claims, counterevidence/rejected hypotheses, open questions, data
gaps, reference-only evidence/snapshot currentness, and typed display bindings
containing case id, immutable snapshot id, Context Epoch, entity/slot,
ClaimRecord/EvidenceReceipt references, and necessary currentness. Host-owned
evidence, claim, entity-binding, and snapshot state is not compressed into
model prose; the post-compaction context compiler retrieves the relevant
verified subset.
Complete identifiers, reverse mappings, raw rows, reasoning, and unrestricted
tool results remain excluded.

Missing, unknown, failed, cancelled, stale, superseded, historical, and
unverified states remain explicit and cannot become zero, completed, current,
passed, or verified across repeated compaction. Automatic compaction does not
create evidence authority or model-summarize protected state. Manual
compaction remains available and distinguishable from `auto=true` events.
The formal packaged Milestone A row intentionally invokes manual `/compact`
through the visible UI and accepts only the resulting durable nonzero
`auto=false` item with source digest/ancestry, then proves exact recovery and a
short provider continuation after fresh relaunch. It does not require a
64-KiB single read, three text anchors, a large tool result, or an automatic
threshold crossing. The 75%/85% automatic contract remains a separate
deterministic production-Go focused/integration proof: at most one automatic
compaction per admission, re-estimation, and zero provider calls with the fixed
blocker when the exact request remains over the hard threshold.

Packaged funds acceptance must prove case analysis and source-exact local
display continue after real compaction by re-resolving the binding against its
original retained immutable snapshot. If that snapshot was explicitly deleted
or its binding fails verification, the slot displays `source unavailable`
rather than using a current snapshot or persisted PII prose. The
implementation may fail a case continuation closed only when its exact typed
state cannot be safely reassembled, without disabling ordinary work.

Alternative considered: reuse the existing fixed summary and retain only the last two turns. Rejected because it loses active Goal/Todo/constraint semantics and cannot prove that repeated compression preserves unresolved evidence state.

### Decision 7b: Todo failure and cancellation are durable typed states

Parent and child Todo state uses one closed lifecycle: `pending`, `in_progress`, `completed`, `failed`, and `canceled`. Failed and canceled entries carry a required host-enumerated `statusReasonCode`; other states prohibit it. Raw exception strings are not persisted as status authority. Strict inbound validation rejects malformed arrays, duplicate ids, unknown fields, multiple active entries, terminal states without a reason, and invalid transitions without mutating the prior Todo set. Failed/canceled entries remain unfinished for Goal closure, survive restart/fork/resume, and can return to `in_progress` only through an explicit retry transition that clears the old reason.

Alternative considered: represent cancellation by deleting the Todo and failure by a free-form note. Rejected because both erase auditable terminal state and can make an unexecuted task appear complete.

### Decision 8: A single terminal finalizer owns every assistant turn exit

The loop returns an internal terminal candidate, never a directly publishable
assistant string. A finalizer receives the frozen context, registry, tool
outcomes, proposed claims, and terminal reason. It runs for every candidate
capable of producing an accepted assistant event or case-factual slot,
including normal success, source unavailable, no tools, provider/model
failure, cancellation, timeout, interrupted stream, recovery exhaustion, step
limit, approval resolution/expiry, user-input resolution/cancel, and any
future factual fallback. Tests enumerate all such producer/return paths and
fail when a new accepted-event-capable path bypasses the finalizer.

Resume, restart, and recovery admission are continuity transitions, not
assistant terminals by themselves. They revalidate current context and grants
before they may create a new turn candidate; that candidate then uses the same
finalizer. Background completion is a closed typed lifecycle delivery to an
already-terminal parent and SHALL NOT re-finalize or mutate the parent's
accepted terminal. An explicit continuation created from that delivery is a
new turn and its candidate uses the finalizer. `report_fallback` has no
production emitter and creates no publication; if a future fallback emits an
accepted assistant candidate, terminal-coverage tests require it to use the
same finalizer.

Recovery can request continuation only when it preserves the same
context/grant and cannot improve evidence state. Source unavailable is
terminal host output for the affected case-fact slot and does not call a model
to generate or repair that case fact; ordinary provider work in the same mixed
request remains available under its own grants. Structure repair can
delete/narrow unsupported material but cannot add facts or receipts.

### Decision 8a: Source-exact local display terminates in an allowlisted typed sink

The installation-bound current local Analytix user session, current main-frame
renderer principal, active case binding, and immutable dataset snapshot jointly
authorize standard local display for that case. No third-party, administrator,
per-field legal approval, `PIIProjectionGrant`, controlled artifact, or external
trusted sink is a runtime prerequisite. The active-case UI defaults to
`displayMode=full`; the user may choose `masked`. That choice affects only the
final local projection.

The existing Electron Main/preload typed-bridge pattern owns a dedicated,
short-lived request/response sink that is separate from generic accepted-final,
history, HTTP/SSE, preload/IPC events, and free-form renderer stores. It is one
closed family with four variants:

1. `ImportMappingPreview` binds one host-staged source generation, archive
   member/file identity, parser/schema version, requested row window/fields,
   and expiry before snapshot admission. It returns exact cells only; path,
   archive locator, unrequested columns, and raw DTO payloads remain private.
2. `CleaningDiffPreview` binds one input snapshot, cleaning rule-set digest and
   generation, output snapshot, transformation lineage, requested row/field
   window, and expiry. It returns typed before/after/status values without
   copying raw cleaning logs or generic history payloads.
3. `DirectSourcePreview` binds the current renderer session, active case,
   current immutable snapshot, requested rows/fields, and display mode. Trusted
   host/data-plane code reads only that selection and returns it with zero
   provider, MCP, EvidenceReceipt, ClaimRecord, or Final Gate calls.
4. `AcceptedSlotDisplay` binds the current renderer session to an already
   accepted case/snapshot/ContextEpoch/claim/receipt/entity-slot plus original
   source row/field lineage. After Final Gate, Go re-reads only those fields
   from the retained original immutable snapshot. A canonical private binding,
   current database value, or reparsed approximation is never a display source.

Each response has a bounded page/window, strict closed field enum, no-store
cache policy, in-component display lease, and explicit clear/revoke behavior.
Source-exact bytes are destroyed on page replacement, case/snapshot/generation
change, session/principal/window invalidation, expiry, or component unmount.

No variant can request the private mapping table, key material, DuckDB
path/file descriptor/locator, unrelated columns or rows, raw evidence blobs, or
cross-case identity links. Main rejects a stale renderer/window/session, case
switch, snapshot mismatch, expired request, duplicate carrier consumption, or
late response and clears any prior display payload. Generic events and stores
retain only typed bindings and closed status; they never receive display bytes.

Copy, save/export, print, drag/drop, external applications, Connector, email,
upload, share, and cross-case analysis are separate effects and are not
implemented or expanded by this train. Existing surfaces must not perform an
automatic value-bearing effect, and Provider-bound Connectors remain PII-free.
Any later authorized external-effect work must bind an explicit user action to
the exact target, case, snapshot, and fields and use a typed Main/Go path.
Existing `PIIProjectionGrant`, controlled-artifact, and one-use trusted-sink
mechanisms remain future/existing external-effect controls and never gate the
standard local display seams.

Alternative considered: reuse the legacy import sample DTO, cleaning history/
log response, or return protected values in generic runtime responses,
persist reconstructed answer prose, let a model write the final string, or use
regex/string substitution in renderer Markdown. Rejected because those paths
cannot bind a displayed field to its exact case/snapshot/claim/evidence owner,
cannot revoke stale payloads reliably, and turn generic transport/state into an
exfiltration surface.

#### Slice 5 host-staged Funds import boundary

The Slice 5 production import path is a pre-snapshot, non-authoritative owner
inside the existing Go Funds CSV admission service. Electron Main alone chooses
one canonical workspace-contained source. The Go source adapter freezes that
owner-owned, single-link regular file, checks its identity/size/mtime/hash
before and after reading, and retains only a host-private revalidation closure.
The renderer receives only one or more opaque selectors plus fixed `Source N of
M` labels, ordinals, counts, dimensions, and closed status. It never submits or
receives a workspace, case, snapshot, principal, grant, source path, archive
member name/path, inventory digest, or raw import DTO.

One process owns at most one active import generation. Its identity binds the
current principal and case observation, exact source digest, complete private
inventory, parser policy, closed mapping policy, and random nonce. Reselect,
explicit cancel, case/principal drift, window/renderer loss, expiry, shutdown,
or a canceled/failed confirmation revokes the generation and clears its mutable
exact-value buffers. Confirmation reopens and reparses the same source, checks
the exact source/inventory/canonical digests and row count, revalidates the same
principal/case/generation, then calls the existing canonical Funds admission.
Only that existing path creates immutable raw/parsed/source-row material,
installs the immutable DuckDB source, and advances DSV2 through
`SealedServiceV2.AdmitExactV2`. A native build, material write, authority, or
CAS failure proven before that DSV2 CAS linearization leaves the prior DSV2
head unchanged. Once the CAS succeeds, later authority drift or HTTP response
loss is outcome-unknown to the caller rather than a rollback claim; the
existing current DSV2 authority is the reconciliation seam.

This slice deliberately does not persist the selected original CSV/ZIP or its
archive inventory as a durable raw authority. Before confirmation they are
bounded process memory only and disappear on restart. At confirmation the
existing admission receives a deterministic UTF-8 canonical 34-column CSV
constructed from the closed mapping; that canonical accepted CSV, not the
original ZIP container or member locator, becomes the authoritative admission
source. Import Mapping Preview continues to display the decoded source cell
without padding, truncation, reformatting, or substituting a canonical value.
This distinction must remain visible until a later accepted design explicitly
requires durable original-container recovery.

The supported input envelope is intentionally fixed:

- ordinary `.csv`, or `.zip` whose every item is a supported regular `.csv`;
  no XLS/XLSX, 7z, RAR, password/encrypted ZIP, nested archive, ZIP64, external
  extractor, Python backend, or alternate runtime;
- strict UTF-8 with one optional leading BOM, otherwise strict round-trip
  GB18030; illegal or ambiguous bytes fail closed;
- at most 64 MiB compressed source bytes, 16 ZIP members, 48 MiB expanded per
  member, 64 MiB expanded in aggregate, and a 200:1 per-member and aggregate
  expanded/compressed ratio after a 1 MiB allowance;
- at most 100,000 aggregate data rows, 64 source columns, 16 KiB header bytes,
  4,096 UTF-8 bytes per source cell, 64 MiB canonical admission bytes, a
  1 MiB typed response, and a ten-minute staging lifetime.

The current source-file owner/link identity implementation is admitted on the
verified Unix host shape only. Windows fails this acquisition closed until a
platform-specific owner and hardlink identity implementation and tests exist;
it is not inferred from the macOS candidate.

ZIP inventory normalizes only NFC, case, and `/` ordering inside the private
owner. Absolute, drive/UNC, backslash, dot-segment, control/NUL, normalization
collision, case collision, duplicate, directory, symlink, hardlink/special,
encrypted, unsupported-method, corrupt/truncated, checksum/size-mismatched, or
budget-exceeding members fail closed and are never extracted to a directory.
The header mapping is deterministic and closed over the canonical Funds fields
and explicitly supported synonyms. Unknown, ambiguous, duplicate-source,
duplicate-target, missing-required, width-drift, cell, encoding, or row parse
errors cannot be silently converted into facts or confirmed.

`ImportMappingPreview` is mounted in the existing Session Header data-import
modal, defaults to full display, offers masked display and bounded paging, and
stores exact response bytes only in its component-local lease. It is not an
EvidenceReceipt, ClaimRecord, Final Gate result, history item, runtime event, or
Provider/MCP surface. The browser shim remains unavailable and this Slice 5
boundary does not itself provide the later Cleaning Diff producer.

#### Slice 6 deterministic Funds cleaning boundary

The accepted Cleaning Diff contract requires immutable input/rule/output
lineage but does not require preview-before-commit or a cleaning-specific
prepare/confirm/cancel lifecycle. The legacy cleaning UI's action is a direct
clean/reclean operation, while its old Python/data-engine implementation uses
an absolute database path and in-place updates. Slice 6 therefore does not
copy the Slice 5 staging protocol and does not reconnect that mutable path.
It performs one closed deterministic operation against the current witnessed
DSV2, advances the existing DSV2 head, and only then mints a short-lived
post-operation CleaningDiffPreview selector.

The existing Funds query-source owner supplies the current immutable DuckDB
through its callback-scoped exact lease. The pinned data-engine native process
receives it only as the inherited, unlinked, read-only FD 3 and receives an
unlinked fixed-schema result capability at fixed FD 5. Its versioned canonical
rule literal and digest cover text, account/card, timestamp, direction,
currency, exact checked-i128 canonical decimal up to scale two, and canonical
empty/null handling.
It emits a stable 34-column CRLF CSV plus ordered changed-row/cell inventory;
the Go boundary rechecks the rule, input identity, result digest, output hash,
byte length, row counts, state/status consistency, and ordering before use.
The result digest fixes Go `encoding/json` string escaping as its canonical
cross-language byte representation, with a shared Rust/Go digest vector for
HTML-sensitive and U+2028/U+2029 text.

The canonical Funds builder already rejects non-canonical card/account,
timestamp, amount, direction, currency, and leading/trailing cell whitespace.
The production-reachable formatting rule therefore additionally removes only
ASCII space, hyphen, and underscore separators from optional
`counterpartyAccount`, a builder-admitted field already present in the closed
CleaningDiffPreview allowlist. The rule does not infer account meaning, and it
does not transform non-display balance columns. Every producer-reported
changed row must contain at least one ordered allowlisted changed cell; Rust
generation and Go parsing both reject a changed row with an empty cell list.
The same canonical builder must accept the cleaned CSV, and replaying the
cleaned snapshot under the same rule produces identical bytes with zero
changes.

Rust budgets each changed row before retaining its exact cells. Rust and Go
share the full-result limits of 1 MiB, 32,768 JSON tokens, 100,000 rows, the
closed fifteen-cell maximum per changed row, and 4 KiB per exact value. The
budget covers the complete result wire including `resultDigest`, not only its
digest material. The Go native protocol parser separately adds the exact fixed
26-token `request_id`/`ok`/`data`/diagnostics envelope allowance, so a valid
32,768-token inner result remains reachable without widening the inner budget.
Go private result, row, and cell carriers reject JSON marshal and unmarshal;
their `String`/`GoString` projections contain only fixed metadata, counts,
hashes, and `[PRIVATE]`, never before/after or raw-row bytes. Invalid canonical
input is rejected before DSV2 CAS and does not create an `invalid` preview;
parser-only state tests do not assert production reachability.

The output CSV reuses the existing canonical Funds material builder, private
CAS materials, and `SealedServiceV2` witness CAS. Cleaning calls the same
sealed owner through `AdmitAfterExactV2`, which adds only an expected-current
predecessor check at that CAS base. It owns no new pointer, registry, database,
or protocol. A stale predecessor or any failure proven before the witness CAS
leaves the prior head current. If the CAS may have succeeded but readback,
authority validation, or the Main response is lost, the result is
`outcome_unknown`; no rollback is attempted or claimed, and reconciliation is
through the current DSV2 owner.

The cleaning admission distinguishes `pre_cas_failed` only when control flow
proves the DSV2 CAS was not called or a fresh current-snapshot reconciliation
still resolves the expected input. A CAS error that resolves the output, a
different head, or no trustworthy current head remains `outcome_unknown`.
The Go HTTP route carries proven failure as the closed path-free
`{"status":"pre_cas_failed"}` operation response. Electron Main maps only that
exact response to local `unavailable`; transport loss, a non-success HTTP
response, malformed bytes, and post-CAS/currentness ambiguity remain
`outcome_unknown`. The production Main typed-local transport allowlist includes
the fixed cleaning `run` and `revoke` paths; it still rejects unknown, prefixed,
or query-bearing paths before transport.

After a confirmed current output is observed, Go retains the bounded exact
before/after rows only inside one ten-minute component-local generation.
Selector, current output DSV2, case binding, principal, requested fields and
window are revalidated before and after each callback. Rerun, case/principal
or current-snapshot drift, expiry, explicit revoke, renderer unmount, runtime
restart, and shutdown clear or make that generation unreachable. Main stores
only the canonical workspace and closed lineage identifiers; renderer state
stores only the operation result metadata and the existing ephemeral preview
component stores returned exact cells. Browser fallback remains unavailable,
and no Agent, Provider, MCP, receipt, claim, Final Gate, generic history,
event, log, or telemetry path participates.

### Decision 9: Current-run MCP readiness is native and case-bound

Before advertising a case source, the runtime performs a current-run native probe that proves connected transport, fresh catalog, expected server identity/version, connection epoch, schema hashes, and case-bound health/dataset snapshot. A cached catalog can help parse schemas while disconnected but cannot satisfy readiness or mint a grant. Fake or spoofed `analytix_funds` identity is rejected by configured/pinned identity evidence and case health.

The tool catalog is additive and grant-specific. General tools and ordinary
MCP remain available under their existing workspace/execution policies.
Current case tools are appended only for the current provider request whose
TSCV2/DSV2/source grant is valid, and execution rechecks that same grant. A
case-source failure removes that case tool from later catalogs but does not
remove general tools or invalidate unrelated ordinary effects. A general tool
result can never be reclassified as case evidence.

Protected DuckDB bytes, raw evidence, private entity mappings, and complete PII
are not ordinary workspace resources. They are held behind host-private
locators/descriptors that are absent from ordinary environment, prompts, and
tool arguments. The file broker rejects their stable identity and protected
roots, and a general shell process executes without filesystem capability for
those stores even when it may write the ordinary source workspace. Indirect
paths, symlinks, hardlinks, inherited descriptors, environment variables,
subprocesses, archive tools, and `find`/`grep`/Git access cannot upgrade that
boundary. Only the fixed funds data-plane call under the exact current grant
receives the callback-scoped descriptor. The boundary is enforced at each
data read/effect, not by disabling the Agent or marking the whole thread as a
case mode.

Direct Source Preview is not an MCP tool and is never advertised to or invoked
by a provider. It reuses the same current DSV2 snapshot/data-plane confinement
under the local typed-display request, so its selected values cannot enter an
MCP public result or provider continuation.

This checkpoint is development evidence only. It cannot satisfy the valuable

### Decision 10: Milestone B is one fixed valuable funds query

The production funds MCP adds one fixed business tool,

plus PII-free semantic labels,
time range, timezone, currency/scale, canonical integer-string minor-unit
inflow/outflow/signed net, transaction count, completeness, deterministic

references. Evidence-bearing money never crosses `DOUBLE`, JavaScript

authority but remains auditable from the two exact amount claims. Counterparty
identity is omitted unless separate exact canonical facts support it. The

settlement; later display re-resolves only the accepted retained binding from
its original witnessed DSV2. A partial/truncated/cancelled/timed-out query
cannot become a complete claim.

Alternative considered: import the whole historical
`duckdb-workbench-runtime.mjs`, expose `run_case_sql`, or return raw

and ordinary masking boundary.

### Decision 10c: Source-exact PII is local-display data, never model or generic state

Source-exact PII remains outside provider/model context, provider
continuations and history, subagent inputs/results, MCP public results,
ordinary tool public projections, generic HTTP/SSE text or event fields,
free-form durable conversation text, search indexes, logs, telemetry, crash

receive short typed model aliases, verified necessary semantics,
exact minor-unit amounts, direction, date range, coverage/currentness, and
ClaimRecord/EvidenceReceipt references only.

Standard local source-exact display has the four allowlisted variants defined
by Decision 8a. Import and cleaning views bind staged/input/output generation

accepted-final, history, HTTP/SSE, bridge events, free-form renderer state, and

affects only the local projection and does not alter provider payloads, claims,
receipts, digests, or gate decisions.

The typed local UI never receives the private mapping table, key material,
DuckDB locator/descriptor, unrelated fields, raw evidence blobs, or cross-case
identity links. Existing `PIIProjectionGrant`, controlled artifact, private CAS,

required for Direct Source Preview or AcceptedSlotDisplay, and no new
authority, receipt, registry, CAS, or protocol version is introduced.

Alternative considered: make the controlled-artifact chain the only route to
complete local values or add another receipt/source-authority/registry/CAS
version. Rejected because the current local session/principal/case/snapshot
binding already owns display authority, while the generic-channel boundary can
be enforced through the existing typed seams.

### Decision 10d: Case investigation state is host-owned, multi-turn, and retrievable

The case capability is not a one-shot tool call or ephemeral prompt. Existing
thread, claim, EvidenceReceipt, snapshot, private-CAS, Todo, compaction, and
accepted-final owners retain a typed investigation projection containing
verified facts, candidate relationships, counterevidence and rejected
hypotheses, unresolved questions, data gaps, prior query scopes, stable entity
references, current/historical snapshot bindings, and display bindings composed
of case id, immutable snapshot id, Context Epoch, entity/slot,
ClaimRecord/EvidenceReceipt references, and necessary currentness. Complete PII
prose is not persisted, and the model's prose is not the authority for this
state.

The current per-thread `thread-context-v1` record is not sufficient for a
newly created independent thread because it requires an exact thread id and
generation and has no latest/list operation. Add the minimum case-level
longitudinal index inside the existing caseentity owner: immutable entries bind
tenant/user/case/binding, case-state generation, snapshot/currentness, entity
AuthorityEntityRefs and StableOrdinals, and claim/evidence/continuation digests.
A new thread rehydrates only after the user explicitly binds that same case and
the host revalidates current TSCV2/DSV2; there is no last-opened/current alias,
ambient case discovery, global reverse map, second registry, or generic Memory
fallback. The new thread receives provider-safe aliases and typed semantics,
not exact values or old prose.

Five memory tiers stay distinct: process/turn working set; thread typed
continuation plus provider-safe history; case longitudinal typed investigation
state; retained immutable snapshots/evidence/accepted-final bindings; and the
user-approved general Memory registry. Only the last is general free-form
memory, and it remains manual/store-only. `MemoryRecord.content` MUST NOT
automatically capture or contain case PII, raw case facts, case reverse maps,
AuthorityEntityRefs, aliases used as case state, source paths, raw tool bodies,
or retained-snapshot substitutes.

At each continuation the host retrieves the bounded subset relevant to the
current question. Restart, resume, and permitted fork revalidate the current
case/epoch/snapshot before assembly. A subagent receives only its delegated
entity references, semantic features, query scope, evidence references, and
allowed tools; it receives no complete PII or reverse mapping, and its typed
result must bind the parent thread, delegated case, snapshot, epoch, receipts,
and claims before the parent may use it. Background or stale child text cannot
become case state.

If all eligible typed state cannot fit, retrieval uses one deterministic
priority: current verified facts, historical comparison facts, key
relationships, counterevidence and refuted findings, data gaps, evidence/claim
references, then current-versus-historical snapshot differences. Selected
items retain exact coverage, currentness, and evidence binding; truncation
cannot promote omitted or lower-authority state.

On reopen, restart, resume, permitted fork, independent-thread rehydration, or
compaction, the host revalidates
the typed display binding and resolves it against its original immutable
historical snapshot. That snapshot and binding remain retained for as long as
the history entry remains openable. Explicit deletion or validation failure
fails closed as `source unavailable`; the host never substitutes current
snapshot values or a remembered prose value.

On snapshot update, current Direct Source Preview uses the new active snapshot,
while a historical Agent result keeps resolving its bound old snapshot. On case
switch, snapshot/context change, renderer session change, window destruction,
or principal invalidation, Electron Main clears or revokes old typed display
payloads and pending responses; any late cross-case response fails closed. The
new epoch prevents evidence, references, private results, provider
continuations, Todos, child results, compaction state, and source-exact display
payloads from crossing the boundary. Reacquiring valid authority in the same
Agent restores the case tool without replacing the Agent or losing ordinary
work.

Alternative considered: rely on the model's conversation summary, generic
Memory, last-opened case, or rerun every query after restart. Rejected because
free text cannot prove evidence binding, generic Memory lacks case/snapshot
authority, ambient selection can cross cases, and reruns cause identity drift
and historical/current confusion.

### Decision 10e: Fields use explicit transformations, not one generic masking algorithm

Every field is classified before projection. Direct identifiers (name,
identity/passport/tax/organization code, account/card/payment/wallet, phone,
email, address, IP/MAC/device, transaction/order/voucher/case identifier,
filename/path, free text/OCR/media metadata, biometric/signature) stay exact in
trusted local storage and typed local UI; provider admission is normally a
ModelEntityAlias, a task-necessary closed semantic enum, a declared aggregate/
range, or withholding. Free text is locally parsed as untrusted content and
never becomes identity or evidence without deterministic extraction and source
lineage. Evidence/provenance identifiers are opaque scoped refs; operational
metadata is limited to fixed code/count/timing/schema versions.

Analytical exact semantics are different: money uses integer minor units or
exact decimal plus currency/scale; direction, count, coverage, missing/null/
invalid, bounded query predicates, evidence/currentness, and necessary graph
direction/topology remain exact. Time, merchant/institution/branch, geography,
degree/rank/community/path, and rare combinations are quasi-identifiers: admit
their least identifying task-sufficient form only after a combined-risk check,
and never add noise/buckets while claiming exact case analysis. The trusted
DuckDB/Funds layer performs canonicalization, joins, entity resolution,
aggregation, graph computation, and source-row reconciliation; the model
proposes bounded queries and explains accepted deterministic results.

Alternative considered: one universal redaction function or post-hoc regex.
Rejected because tokenization, pseudonymization, generalization, bucketing,
local extraction, aggregation, and withholding solve different risks, while
universal masking destroys analytical meaning and still misses free-text or
combined quasi-identifier disclosure.

### Decision 10f: Storage, cache, logging, retention, and at-rest controls keep existing owners

Raw/normalized/cleaned exact rows, deterministic materializations, and snapshot
lineage remain in the existing case DuckDB/immutable snapshot owner. Exact to
canonical to AuthorityEntityRef to StableOrdinal mappings remain in the
existing caseentity SecurePrivateCAS. They are not materialized as authority
columns in provider-visible DuckDB views. Thread/case investigation,
claim/evidence/currentness, continuation, accepted finals, and retained display
bindings remain with their existing typed owners. No vector database, graph
database, memory server, or second runtime/database is added.

Factual caches bind tenant, user, thread, case, binding, context epoch,
snapshot, source/schema/parser versions, query/arguments/scope hashes, expiry,
and invalidation. Identity continuity is not a factual cache. Alias resolution
may use only a short-TTL process-local cache keyed by case/binding/epoch and
must revalidate the private store as source of truth. Typed display bytes use a
component-local no-store lease and are destroyed on page replacement,
revocation, expiry, unmount, or authority change. Logs, telemetry, crash
reports, search, and diagnostics admit only fixed codes, bounded counts,
durations, booleans, and schema versions; they exclude exact/canonical values,
keys, paths, raw SQL/tool bodies, case/ref/alias mappings, and source rows.

As built, SecurePrivateCAS protects ownership, filesystem identity, no-follow/
no-replace commit, integrity, and `0600` files but writes plaintext JSON bodies.
DuckDB producer compatibility is pinned to `v1.5.4`; native AES-GCM support is
not authorization to enable encryption. Before either DuckDB GCM or a
randomized AEAD envelope inside the existing CAS can ship, one accepted key
contract must separate identity-HMAC key from data-encryption key, bind Keychain
or equivalent OS wrapping, key id/generation and AAD, logical snapshot digest
from ciphertext blob digest, backup/restore, retained-snapshot migration,
rotation rollback, secure deletion limits, and fail-closed wrong/missing-key
behavior. FileVault or OS profile isolation is defense in depth, not the
product key owner. Deterministic ciphertext/FPE is never a model alias.

The Slice 7 candidate keeps that posture executable without starting the
deferred cryptographic design. `SecurePrivateCASAtRestEncryptionEnabled`
remains false and a synthetic private-CAS contract verifies that current
record bytes are plaintext plus integrity, never content encryption. The same
slice removes the production-reachable renderer flow fact cache and shared
inflight dedup because renderer authority cannot supply the complete trusted
cache identity above. Legacy stats fact functions remain fixed
`source_unavailable`; their UI-only state does not become a fact cache. Alias
resolution remains no-cache and re-reads the existing caseentity private store
under the current TSCV2/DSV2 lease. All four typed-local variants share one
15-second component-local renderer lease with expiry, hidden/page replacement,
unmount, authority-drift, and late-generation invalidation. Case thread search
uses only the closed lifecycle status; Main managed logs and the public console
admit no caller free text and preserve only Main-owned fixed category/event
codes plus exactly allowlisted number, boolean, SHA-256, and schema-version
fields. Child capture uses typed fixed lifecycle/capture records rather than
raw lines. This candidate does not add a sweeper, registry, deletion API, key
store, envelope, migration, or encryption protocol.

The existing `eventlog.Store.Search` recursive value matcher is not called by
the production thread-list route and remains legacy/quarantined rather than an
observability index; wiring it into a product route requires a separate safe
projection first. Retained immutable DSV2/source snapshots still have no
accepted delete owner or TTL. They remain readable only while their existing
typed binding validates; validation or source loss projects `source
unavailable`. Flow-result cleanup is not a substitute for retained-source
retention or deletion. Private task/job lineage remains durable product state,
not a generic log or typed-local exact-value cache; restart recovery closes
running lifecycle state but does not claim age-based deletion.

The Slice 7 P1 correction follows the visible `AnalysisPage` warm path and
removes its second window-global flow cache/shared inflight owner from
`flow-stats-link`; case switches abort outstanding request-local warm calls and
late completions cannot publish success. The generic renderer HTTP client also
stops coalescing GETs because current import, cleaning, case, and flow routes
carry factual state without the complete trusted cache identity. Renderer
`log:error` keeps its preload call signature only for compatibility: the Main
schema discards caller category/message/free-text detail and emits a fixed
host category/event code plus an allowlisted boolean and count.

The subsequent P1-C/P1-D correction binds AcceptedSlotDisplay's validated
thread, turn, and publication-commit receipt identity into the component-local
request generation. A prop replacement therefore withholds the old response
and invalidates its ticket synchronously during render, before effect cleanup,
and rejects its late completion. The Main logger no longer attempts to prove
free-text safety with path/SQL/tool/alias/PII regular expressions: managed-file
and public-console projections ignore caller category/message/string detail,
and retain only closed Main-owned category/event codes with exact scalar key
allowlists. The raw `appendManagedLogLine` entry is removed; the only
production child owner submits fixed typed lifecycle or byte-count/SHA-256
capture records that are normalized again before persistence. Neutral exact
text, file URIs, POSIX/drive/UNC paths, SQL, tool forms, aliases, refs, and PII
therefore have no string-bearing projection to either sink.

P1-F applies the same closed boundary to renderer-owned console paths.
AppErrorBoundary retains only a boolean failure state, renders only fixed
localized fallback controls, and sends the compatibility log call without
Error/message/stack/component detail. Browser-preview logging emits one fixed
renderer diagnostic; rollback success emits nothing; embedded WebGL/wheel and
unsupported-runtime diagnostics emit fixed events without caller payloads.
Existing flow performance consoles remain bound to the closed numeric/enum
snapshot projector, and the other embedded flow/toast diagnostics remain
fixed or allowlisted rather than becoming a second logger protocol.

### Decision 10g: Privacy and token economy are separate gates

Replacing source identifiers with a long AuthorityEntityRef improves boundary
control but does not guarantee fewer tokens. Provider-visible prose and tool
schemas therefore use ModelEntityAlias, while host/evidence state retains the
authority ref. A synthetic, source-free scorecard records bytes and the actual
tokenizer/model/version count for source-shaped identifiers, the current long
ref, short aliases, and safe natural labels. `tiktoken` may score only named
OpenAI-compatible encodings offline; every other provider remains
`UNVERIFIED` until its exact tokenizer is available. Character-count division
is not evidence. Privacy admission passes only with PII zero-byte tests, and
token economy passes only with the provider-specific scorecard; neither gate
substitutes for the other or for semantic/DuckDB-oracle equality.

### Decision 11: Provider families share one local authority gate

DeepSeek/OpenAI chat completions, OpenAI responses, Anthropic messages, and explicit custom endpoints each map their native structured result to the same versioned proposal envelope. If strict schema is unavailable, one structure-only repair is permitted against the existing proposal/evidence set. The host compares fact hashes before/after and rejects any addition or support upgrade. Failure yields boundary-only output.

### Decision 12: Analytix is the sole product baseline

The current Analytix product contract, architecture, implementation, and fresh
public-seam evidence determine product behavior and RC status. External
projects may be researched in Owner-private context when a concrete Analytix
seam needs improvement, but their identity, repository state, comparison
matrix, or research freshness does not enter the product architecture or RC
ledger. Any selected technique is accepted or rejected against Analytix's own
Go Runtime and product contracts, without introducing a second execution core.

### Decision 12a: The RC validation control plane is source-bound and single-execution

Runtime structural correctness is independent of wall-clock latency. Its gate
proves durable-before-publish, first-event/terminal ordering, zero provider
draft or reasoning/PII publication, and the expected provider-attempt and
rejection diagnostics without a latency threshold. The RC performance gate is
a separate controlled benchmark on the currently supported `darwin/arm64`
host profile (`Mac16,8`, Apple M4 Pro, 12 logical CPUs): it binds the exact Git
HEAD/tree, Go/Node toolchains, one `analytix_prod` runtime-server build and its
SHA-256; uses a fresh isolated data/thread root for every run; performs two
unmeasured warmups to establish the reused binary/code-cache state while every
data/thread root remains fresh and cold, then twenty measured samples; computes
nearest-rank p50/p95; and passes only when `first_runtime_event_ms` p95 is at
most 250 ms. Every sample and the
maximum are reported, but the maximum is not a substitute for p95. A different
host is `NOT_CONFIGURED`/`UNVERIFIED`, never a PASS.

The release gate owns a flat execution manifest. Typecheck, runtime build, the
full root suite, ordinary/prod/race Go matrices, structural performance check,
and benchmark each have one manifest entry and execute at most once for the
same source freeze. Nested preflight, product-regression, and speed/cache entry
points may expose standalone workflows, but the release gate does not invoke a
heavyweight child through more than one path. Fresh receipts bind HEAD, tree,
exact command, cwd, toolchain, result, and, where applicable, the exact
production binary. Receipt reuse is limited to a receipt generated and
validated by the same release-gate run; any source, command, toolchain, binary,
or digest mismatch fails closed. Dry-run, skip flags, environment overrides,
and historical receipts cannot authorize the control plane or release.

One logical validation run has two explicit commands. `--execute` freezes the
tested source S, the exact task-ledger hash, a subset of the already defined
closure rows 10.4/10.8/10.9, and one Markdown report path under
`docs/analytix/qa/`. It retains the complete substantive manifest, artifact,
upstream, formal A0/B1, source/toolchain/binary, and receipt checks and the
exclusive same-source run lock. Only substantive success emits
`execution-success-seal.json`; this phase always reports final `passed=false`.
Execution runs through `runtime-go-validation-command.mjs release-execution`
(or the existing release-gate wrapper with `--execute`). The wrapper receives
the seal over its child IPC channel and writes a same-run
`execution-completion-receipt.json` only after personally observing child exit
0 with no signal, spawn error or wrapper interruption. An execution-mode exit
0 means execution succeeded, never final RC PASS. Failed, missing or skipped
checks cannot produce a success seal; abnormal termination after a seal was
written cannot produce the completion receipt or permit final PASS.

After the execution process exits, the Owner may factually close the declared
execution/report/DoD rows and freeze one direct child commit C of S. The
supported closure diff consists solely of those existing `[ ]` to `[x]` bytes
and the predeclared report. Every other task byte, ID, classification,
description, note, order and newline is preserved. The report may be absent at
S or have an exactly frozen prior blob; it must remain a regular 100644 file.
Extra paths, requirement edits, deletions, renames, symlinks, mode changes,
intermediate commits and merges are rejected. This is not a docs-only source
equivalence exemption, and it does not permit real outstanding obligations to
be marked complete.

`--finalize --execution-seal <path>` branches before execution admission or any
heavy command and reads only the same run's frozen receipts. It checks that
the execution process exited successfully using the wrapper's bound completion
receipt; PID absence alone is insufficient. It revalidates envelopes, byte hashes, substantive
projections and original source bindings, verifies exact S-to-C Git objects
and the closed checkbox diff, and requires a valid ledger with zero open
RC_REQUIRED rows. Package, A0/B1 and other receipts stay bound to S; the final
receipt separately names testedSourceS and closureSourceC. Only this phase
emits final `passed=true`; an identical-input repetition returns the existing
immutable receipt, while changed input is rejected without overwriting it.
Final adjudication writes no source, task ledger or Git index and executes no
heavy checks. It may write only the final receipt in the existing run.

The report contains the fixed 10.8 sections: Root cause, Architecture,
Implementation files and lines, Commands and results, Metrics, Package
result, Residual risks, Unverified platforms and external environments, and
Final aggregation. It binds the execution run/seal and every same-run receipt
digest; Final aggregation remains `pending` in C because the immutable final
receipt is the later verdict. Structural completeness does not prove the
truth of the prose or discharge the Owner's factual review of 10.8/10.9. The
final receipt does not require another edit to the frozen report or ledger.

Artifact admission is artifact-bound. It inventories the exact packaged files
and production dependency closure and fails only when a concrete artifact
entry has an unmet mandatory LICENSE, NOTICE, copyright, attribution, or
redistribution obligation. Research checkout state, historical starting point,
product lineage labels, comparative freshness, or a private authorization
ledger is not a product gate. A failure must identify the exact artifact entry,
the governing license or authorization term, and the missing required action;
otherwise it cannot block packaging.

If the controlled p95 fails, the receipt must report PII-free phase evidence
for HTTP admission, history read/preflight, durable append/fsync, and SSE
publish before any optimization. A phase that cannot be attributed remains
explicitly unavailable and blocks optimization and the performance gate; the
same frozen source is not blindly rerun to select a favorable sample.

### Decision 13: Layer ownership follows the Go target architecture

- Pure identities, hashes, normalized claims, receipt invariants, answer unions, and publication values: `internal/domain`.
- Turn context, grant service, outcome verification, claim verifier, finalizer, report publication use cases: `internal/app`.
- Source probe, receipt registry, snapshot store, report renderer/publisher, identity verifier interfaces: `internal/ports`.
- HTTP/SSE request and accepted-event encoding: `internal/adapters/inbound/{httpapi,sse}`.
- MCP, provider, event log, files, data snapshots, report artifacts: `internal/adapters/outbound`.
- Production assembly and mandatory gate enablement: `internal/runtimeapp`.
- `internal/server` remains a compatibility facade and delegates to these owners; no new separable evidence behavior lands there.

### Decision 14: DOCX is a Desktop Host artifact, not an Agent or funds tool

Desktop Main therefore parses plain text or Markdown with a fixed GFM document
AST and maps only an allowlist of nodes to the MIT `docx` document model. The
mapping covers headings, paragraphs, emphasis, lists, tables, workspace-local
images, safe hyperlinks, explicit page breaks, alignment, A4 layout, and
East-Asian font names. Unsupported or raw HTML remains inert text or is
rejected; it is never handed to an HTML converter. Images are size- and
format-bounded, read only after canonical workspace containment, embedded in
the ZIP package, and never referenced through an external relationship.

Electron Main derives the active Write workspace from current settings,
requires the current main frame, resolves the current source inside that
workspace, applies the ordinary masked/no-reasoning projection, owns the save
dialog and final file write, and returns only bounded status. The renderer
cannot choose a workspace authority. The generator makes zero Agent, Provider,
MCP, claim, or Final Gate calls and spawns no child process.

The funds plugin neither imports nor calls the generator. A future or existing
funds factual report use case may submit an already Final-Gate-accepted typed
artifact model to the host builder only through the separate report
publication authority and atomic publication pipeline. Ordinary Write remains
masked and cannot assert that authority. This reuses the existing publication
contract and adds no artifact registry, grant, CAS, receipt family, or protocol
version.

Alternatives rejected: keep `html-to-docx` plus an npm override, because the
vulnerable parser remains inside the bundled graph and arbitrary HTML remains
the input model; use an external native document runtime, because process tree,
size, license/SBOM, signing, sandbox, and cross-platform package admission are
absent; use `docxtemplater`, because it
requires a pre-existing OOXML template and is not a direct Markdown AST
writer; use `officegen`, because its older archive/dependency model does not
improve this boundary.

## Risks / Trade-offs

- [General startup remains coupled to funds/PII] -> Make plugin,
  dataset-selection, evidence, report, and controlled-artifact initialization
  degradable; packaged A explicitly runs with them absent.
- [Startup degradation becomes a hidden Agent mode] -> Keep one runtime and
  one ordinary catalog; record each unavailable optional capability and deny
  only its concrete data/effect instead of starting a second configuration.
- [Unreviewed implementation work mixes A, B, PII, and V3/V4 authority] ->
  Preserve all task-external bytes, freeze expansion, inventory ownership, and
  stage only reviewed vertical-slice hunks after fresh verification.
- [Narrow funds query accidentally reopens arbitrary SQL or paths] -> Expose
  one fixed typed operation through a callback-scoped DSV2 handle and the
  bounded packaged data plane; deny raw path/SQL in every public contract.
- [Funds result leaks complete PII] -> Select minimal native fields, project
  stable case-scoped references before provider/ToolOutcome/receipt/claims,
  negative-scan every forbidden generic channel, and separately prove the same
  sentinel appears only in the allowlisted typed local sink.
- [Typed display returns stale, unrelated, or cross-case values] -> Bind every
  request and response to the current renderer session/principal, exact case,
  immutable snapshot, epoch, rows/fields, and expiry; consume Agent private
  carriers exactly once and reject late responses after case/snapshot/window
  change.
- [History silently shows current values for an old answer] -> Persist only the
  typed binding, retain its immutable historical snapshot while openable, and
  re-resolve that snapshot or show `source unavailable` on deletion/validation
  failure.
- [Vision Bridge bypasses provider privacy] -> Apply the same host privacy
  projection before bridge and native-vision dispatch, permit only a trusted
  local safe derivative, and keep the image effect unavailable with zero
  provider calls when that component is absent.
- [Masks or per-turn aliases merge/split entities] -> Derive a
  collision-resistant case-scoped reference with host-private key material,
  derive the short alias only from the persisted StableOrdinal, preserve both
  through the existing private owner, and fail on ambiguous resolution,
  correction, migration, or unsupported entity type.
- [Independent thread inherits the wrong case] -> Require explicit same-case
  selection, current TSCV2/DSV2 revalidation, and an immutable case-level index
  in the existing caseentity owner; prohibit last-opened/current aliases and
  generic Memory fallback.
- [Exact timestamp/merchant/graph tuple re-identifies a subject] -> Apply a
  task-specific combined quasi-identifier budget and withhold or generalize only
  the non-essential tuple while retaining exact money, coverage, direction,
  evidence, and currentness semantics.
- [At-rest encryption breaks snapshot identity or retained history] -> Keep it
  disabled until key ownership, logical versus cipher digests, backup/restore,
  rotation, crash rollback, and retained-snapshot migration pass synthetic
  compatibility tests.
- [Ordinary read/bash bypasses the funds tool] -> Keep protected sources and
  reverse mappings outside ordinary workspace authority and prove file,
  shell, subprocess, symlink/hardlink, descriptor, environment, Git, and
  archive bypasses fail at the concrete effect boundary.
- [Snapshot refresh makes old facts appear current] -> Preserve entity
  continuity separately from receipt/claim snapshot currentness and project
  old facts as historical/stale/superseded until reverified.
- [Aggregate claims cannot represent signed net directly] -> Reuse exact
  directional ClaimAmount plus ClaimCount and derive signed net only in the
  deterministic renderer after same-scope Final Gate acceptance; do not create
  a parallel claim authority.
- [Existing native stats use floating-point money] -> Reuse their
  case/materialization/read-only/result-signature controls, but implement the
  fixed operation with exact DECIMAL/text-to-minor-unit conversion before any
  receipt-eligible result.
- [False blocking from incomplete source semantics] -> Use explicit
  partial/unresolved envelopes and acquisition guidance; never recover by
  guessing.
- [Automatic compaction hides work state] -> Compact only once per admission,
  retain host-owned entity/claim/counterevidence/gap references outside model
  prose, carry strict continuation ancestry, preserve
  unfinished/unverified/stale states, and verify real packaged recovery.
- [Historical evidence or window appearance is promoted to delivery] -> Require
  fresh formal packaged public-seam scripts and retain blocked/unverified rows
  separately.
- [Rollback weakens safety] -> Roll back only to a release that preserves
  general Agent availability and keeps unsupported case facts boundary-only;
  never restore the TypeScript Agent Runtime.
- [External platform/credential/legal-effect availability] -> Record formal
  export/share, legal-characterization, provider, signing, and platform rows as
  blocked or unverified truthfully without turning them into prerequisites for
  standard local display.
- [DOCX ZIP is structurally valid but renders differently] -> Inspect OOXML
  parts and relationships deterministically, reopen representative fixtures,
  exercise the installed WPS application on macOS, and keep Microsoft Word
  compatibility unverified if Word is not installed rather than inferring it.
- [Document images escape the workspace or exhaust memory] -> Canonicalize
  each image under the Main-owned workspace, reject external/symlink escapes,
  unsupported signatures, external relationships, excessive count/bytes/
  dimensions, and generate entirely in the Main process without a child.

## Acceptance

B1 deterministic local-display acceptance uses both negative and positive
evidence. Its formal/provider result remains separately gated:

1. Import Mapping Preview/full shows only requested source-exact cells from one
   staged generation and no path/archive locator/generic wizard raw DTO;
   replacement, expiry, or admission clears the lease.
2. Cleaning Diff Preview/full shows only requested before/after/status cells
   bound to exact input snapshot, rules generation, output snapshot, and
   transformation lineage; raw cleaning logs/history remain outside the sink.
3. Direct Preview/full shows the requested source-exact current-snapshot
   rows/fields, makes zero provider/MCP/EvidenceReceipt/ClaimRecord/Final Gate
   calls, and returns no unrelated fields.
4. Direct Preview/masked returns a host-produced masked projection and creates
   no provider, durable-PII, or external effect.
5. Agent Result/full keeps provider request/result PII-free, consumes the
   private carrier exactly once, verifies matching receipt/claim/gate bindings,
   and displays source-exact values read from the original retained snapshot
   row/field lineage, never from canonical binding or current database state.
6. Agent Result/masked reuses the identical provider, evidence, claim, digest,
   and gate artifacts; only the final local projection differs.
7. Reopen/restart/fork/compaction and explicit same-case independent-thread
   rehydration keep history/free-form prose/provider
   continuation PII-free, retains typed bindings, and resolves the original
   immutable snapshot; missing retained source displays `source unavailable`.
8. Any existing copy/export/share/print/Connector/email/upload surface performs
   no automatic source-exact disclosure; adding or exercising a new external
   effect is outside this train.
9. Case switch clears the old display session/payload/pending response and
   rejects late cross-case delivery.
10. Snapshot update moves current preview to the new snapshot while historical
   Agent results continue resolving the old immutable snapshot.
11. Cross-case work requires explicit selection of the exact case set, keeps
    references case-scoped, and delivers no cross-case reverse mapping to the
    model or UI.
12. Same-case two-thread, case A/B unlinkability, merge/split/correction,
    canonicalizer upgrade, and identity-key rotation fixtures preserve or
    revoke aliases exactly as specified and fail closed on incomplete state.
13. Account, card, identity-number, phone, address, device, transaction id,
    path, OCR/free-text, and quasi-identifier combination sentinels are absent from
    every forbidden generic channel, while a separate positive assertion proves
    the same sentinel can appear in each applicable allowlisted typed local
    sink. A global
    UI/DOM zero-byte assertion is not an acceptance criterion.

The legacy B harness's legal-authorization attestation and controlled viewer
as the only full-value route are explicitly incompatible with this acceptance
model and must be removed or replaced before that harness can establish B1.

## Open Questions

- The exact authorized case/DuckDB acceptance snapshot and provider credential
  are external test inputs for the packaged Agent row. Formal external
  export/share targets, lawful-purpose inputs for legal-characterization or
  regulated effects, and optional trusted sinks are separately recorded; their
  absence does not block standard local source-exact display.
- macOS is the current executable package target. Windows/Linux and formal
  signing/notarization remain unverified until their approved environments are
  actually available.
- Full source-specific legal-characterization combinations and formal report
  expansion remain later domain-owner decisions and cannot be inferred from
  the funds-flow, typed local-display, or explicit external-effect acceptance
  rows.
- The first implementation slice supports only account/card aliases. Extending
  person/organization/phone/device/merchant entity ownership waits for closed
  canonicalizer and merge/split/correction requirements; it is not inferred
  from the vocabulary in this design.
- At-rest encryption remains a recorded decision gate, not an enabled feature,
  until the key/backup/retained-snapshot migration contract and cross-platform
  implementation evidence exist.
