# Migration

Status: Normative migration attachment for this change.

## Principles

- New saves are versioned and fail closed; no dual-write to legacy evidence/final/report shapes.
- Historical free-form assistant text, evidence ids, reports, caches, and tool results remain readable only as `legacy-unverified` and cannot support new claims.
- The accepted Context Epoch foundation is reused first; no parallel case epoch is introduced.
- A rollback cannot restore free-form high-risk publication.

## Versioned Records

Add explicit schema versions for security context, grants, outcomes, `PublicToolResultProjectionV1`, evidence receipts, claim records, final envelopes, source snapshots, PII projections, controlled artifacts, and publication receipts. Unknown future versions are preserved for audit where safe but excluded from support/publication.

Canonical hash serialization uses stable field order, explicit null/unknown semantics, normalized time/currency/identifier values, and full SHA-256. Truncated display identifiers never replace integrity hashes.

## Thread And Epoch Migration

1. Introduce the generic default Context Epoch metadata from `context-epoch-foundation` without changing the default no-source provider prefix.
2. On the first new high-risk turn, resolve real workspace/case binding/source manifest/dataset snapshot and accept a case-aware epoch snapshot.
3. Do not infer a current dataset snapshot from legacy assistant text or reports. If no immutable snapshot can be resolved, return `NeedsEvidenceAnswer`/`SourceUnavailableAnswer`.
4. Mark old pending approval/input/job records without context digest/grant as stale. Do not execute them after migration.
5. History/compaction/provider composition includes only accepted new final envelopes and verified tool results for high-risk facts; legacy entries are display-only.
6. New ordinary tool-result writes contain only the exact closed public item plus `PublicToolResultProjectionV1`. At read time, legacy `output:any`, unknown root fields, inline media/paths, remote citations, arbitrary result codes, and mismatched context/tool/grant bindings become `legacy_output_withheld` and cannot be used to reconstruct evidence or artifacts.
7. P1 migration remains open until one sealed, journaled startup plan moves any retained legacy raw tool-result material into an authorized private audit store or deterministically removes it from ordinary `thread.json`, `messages.jsonl`, and `events.jsonl`. Migration never infers artifact/evidence authority from legacy ids, filenames, paths, `dataUrl`, `attachments`, `files`, `citations`, or model/tool claims. Every pre/post-intent, private-store, ordinary-store replacement, and settlement crash cut resumes idempotently before listener activation.

## Evidence Registry And MCP Authority Migration

1. New registries first create and sign the complete capsule and next global index in memory, then durably install the content-addressed capsule blob, and finally atomically replace the installation-key-signed root index. The root index is the only membership commit point. Per-turn capsule/JSONL projections are written afterwards and are never promoted on their own.
2. The signed index binds installation id, generation, previous-index digest, canonical ordered entries, and exact single-entry registry extension. A foreign-key capsule, sequence jump, alternate prefix, duplicate/projection-key collision, non-canonical JSON, or changed predecessor rejects before replacement. A provable pre-replace failure removes only the exact uncommitted blob and is retryable; an ambiguous post-replace failure poisons the live store until restart revalidates persisted authority.
3. A trusted legacy signed head plus an exactly matching ledger may be upgraded only by the global read-only startup plan without changing membership or sequence. A non-empty unsealed legacy ledger cannot be signed as current: after settlement/marker verification, every active legacy receipt is deterministically revoked with `legacy_unsealed_registry_cutover` before new authority is issued. Empty unsealed residue and mismatched dual files remain boundary-only.
4. Missing or complete-record exact-prefix projections may be rebuilt from the unchanged indexed capsule after the global startup preflight. Mid-record, longer, divergent, wrong-key, symlinked, unsafe-hard-linked, or unknown state aborts before repair. Recognized same-inode CAS link/unlink temps and rename temps are non-authoritative repair residue; cleanup occurs only after the global read-only inventory.
5. Superseded content-addressed capsules are garbage-collected only after the new root index is durable. Any retained orphan must validate under the installation key and be an exact historical prefix of the indexed current capsule; a newer/divergent orphan blocks as rollback evidence.
6. Enroll an independent monotonic witness before enabling executable high-risk V2 contexts. Advance signed authority indexes only by exact expected-generation/digest CAS; persist immutable intent and receipt records, then repair the local head projection from the live witness. Signatures, local generations, Keychain/DPAPI/libsecret, or maximum-directory scans are not latest-state proof.
7. If the witness is unavailable, invalid, replayed, equivocated, ahead of missing local material, behind a local projection, or enrollment state is inconsistent, startup and every later effect/publication check keep high-risk work boundary-only. They never re-enroll over existing state or promote a local candidate by generation.
6. Historical `mcpv1` identities and MCP 2024 records remain parseable only in the legacy audit/replay projection. New source probes, grants, outcomes, receipts, membership resolution, and publication require a fact-capable negotiated MCP revision bound into `mcpv2`.
7. Migration is journaled and idempotent. Authenticated recovery of an already-issued old transaction is a distinct pre-baseline phase; after it settles, every owner root is recaptured from scratch. No new registry, settlement, accepted-final, event, memory, reasoning cleanup, authority namespace/bootstrap, or MCP connection may occur until every security-relevant root has passed the composite read-only fixed-point inventory. Acquiring an OS coordination lock may be effectful but creates no product authority; creating a journal, marker, retirement, control, or signing namespace is not a lock exception.

## Authority Advance Journal V1 To V2

1. Freeze the existing V1 root enum, union fields/tags, canonical bytes, signature domain, digest domain, evidence-successor bytes, committed/superseded settlement bytes, and range-reference bytes with deterministic grammar fingerprints and wire goldens. V1 never gains a genesis enum or union branch.
2. New genesis and successor writes use true V2 intent/settlement payloads, V2-only signature/digest domains, explicit reference versions, and `<authority-journal>/v2/{intents,settlements}`. Do not dual-write, re-sign, rename, or silently parse an expanded V1 payload as V2.
3. Before V2 activation, acquire the authority-writer migration lease and complete a read-only V1 fixed point: every V1 intent has an exact committed or fully range-validated superseded settlement; no V1 intent is unresolved; no V1 writer/in-flight request remains; and the current manifest, installation/enrollment, authority profile, credential profile, and fresh witness tail all agree.
4. Persist one idempotent activation marker binding that fixed-point digest, installation/enrollment, namespace, authority profile, credential profile, exact live witness checkpoint/observation, V1 terminal count, and V2 schema/domain fingerprints. Disable the V1 writer and activate the V2 writer in the same exclusive migration boundary. A late V1 write, changed tail, missing record, ambiguous commit, or marker mismatch quarantines the namespace.
5. V2 committed/superseded ranges are all-V2 after activation. A V2 candidate may start from the fixed V1 tail checkpoint, but an unresolved V1 candidate is never converted into a V2 record. Unknown versions and any previously emitted expanded-V1 genesis bytes remain audit-only quarantine material.
6. Existing unversioned journal directories are never a fallback. If they exist, a dedicated migration planner must prove their exact frozen V1 grammar and byte-preserving inventory before no-replace copying into a versioned audit root; otherwise startup remains boundary-only.
7. Windows/Linux compile evidence does not satisfy this migration gate. The protected-DACL/ACL, hardlink, ADS, FileID/inode swap, stable-read, no-replace, restart, and concurrent-writer scenarios must run on the claimed host/CI platform before that platform is marked verified.

## Funds Plugin Migration

1. Remove all factual lookup/write aliases using `active`, `current`, last-opened, or missing-case fallback before enabling new caches.
2. Invalidate pair amount, entity profile, frontdoor, and report caches that lack binding/epoch/snapshot/source/query hashes.
3. Change evidence/claim defaults from `supported` to `unsupported`/`unresolved`; non-host ids remain references only.
4. Replace broad execution registry dispatch with the current advertised capability-bundle allowlist and complete strict input/output schemas.
5. Disable the current local full-case report fallback. Migrate report output to staging and publication receipt; `write_report=false` is zero-write.
6. Move generic audit artifacts from the global cross-case directory to authenticated context-scoped storage with PII projection and retention metadata.
7. Preserve raw inputs as immutable snapshots rather than rewriting existing raw files. Derived tables/records record parser and lineage versions.

## Desktop Contract Migration

- Add shared read-only types needed to display accepted final variants, blockers, coverage, masked citations, and publication state.
- Renderer ignores/suppresses reasoning events even while older runtime data is visible; export paths remove legacy reasoning blocks.
- Existing UI components remain, but case-fact rows originate only from accepted final events.
- Keep the Electron background-task compatibility IPC stateless and fail closed. It does not instantiate a registry or open `background-tasks.json`; list/snapshot return no tasks, register/kill/restart are retired, and output exposes no caller- or storage-derived identity/status/size. Renderer task UX reads the Go thread-summary/task authority only.
- Inventory `child-runs/job-N.json`, retired `job-N.log` files, and the distinct Electron user-data `background-tasks.json` through owner-specific read-only adapters under one composite fixed point and shared activation barrier. The Electron file is an opaque strong-identity/full-SHA-256 input and is never JSON-decoded for migration authority. Unknown files, malformed near-match names, symlinks, special files, external artifact paths, or security-bound record mutations fail closed with zero live-root mutation. After every owner plan validates, an owner journal may authorize only exact monotonic deletion of the legacy Electron file plus durable absence readback; the design does not place it in the Go `RootSet` or pretend all roots share one owner journal.
- No deprecated bridge alias or runtime backend switch is added.

## Report Migration

- Existing reports without a publication receipt are labeled legacy/unverified and cannot be re-delivered as verified artifacts.
- Re-publication requires re-query against a current immutable snapshot, new claim validation, PII projection, render inspection, atomic publish, and a new receipt.
- Existing paths, filenames, renderer blob URLs, save targets, nonempty artifact ids, and self-reported PII grants never migrate into controlled-access authority. A new host-issued opaque handle and one-use slot must resolve to the current committed publication graph. Startup verifies the complete private access journal and closes every open crash cut as full-length `release_indeterminate` before controlled access can activate.

## Runtime Process Authentication

1. A managed desktop launch with no persisted runtime token mints a cryptographically random per-process token in Electron main memory. The token is passed to the Go child through its environment and reused by main-process HTTP/SSE clients; it is not written to settings, argv, READY output, logs, history, or renderer state.
2. An empty token no longer implies unauthenticated mode. Unauthenticated loopback operation requires an explicit `insecure:true`/`--insecure` selection.
3. A standalone authenticated `runtime-server` or `analytix serve` launch without a supplied token fails closed instead of using a static default token.
4. After the Go host captures the bearer token, it removes that token from the process environment. MCP, shell, command-probe, and git children receive a sanitized environment; MCP configuration cannot reintroduce reserved host bearer/provider secrets.
5. Explicit insecure mode is loopback-only. Runtime READY is a closed boolean-only production schema with a loopback URL; missing persistence/production proof, extra credential/path fields, or a listener/diagnostic address mismatch fails closed.

## Native Data Component Packaging

1. Rust remains limited to the exact four existing data-plane helpers frozen in `scripts/native-components.json`; the strict loader recursively freezes every entry as `agentCore:false`, its focused data-analysis consumers, execution probe, target set, and immutable authorization commit. Tauri remains globally forbidden.
2. Cargo builds use an explicit package target triple and write through a same-target ownership lock into a temporary sibling stage. The published stage is invalidated before replacement and receives its receipt only after every binary is durable and reverified, so a failed or concurrent build is unavailable rather than stale-authoritative. A flat ignored `runtime/` helper is never package authority.
3. Manifest schema v4 and receipt schema v5 form the shared Node/Python/desktop/Go contract. They bind the raw registry hash, complete four-root source-closure hash, per-component source/Cargo.lock and effective-build-environment hashes, frozen Rust toolchain identity, target triple, raw build hash/size, signing-invariant payload hash/size, parsed Mach-O/PE/ELF executable structure, and a host-issued Go execution-probe receipt. The only currently implemented authority class is `local_provisional`; release consumers reject it by default until the later controlled release authority is implemented. Cargo builds from a verified immutable source snapshot into an isolated target with `--frozen`; source closure and toolchain identity are checked before and after build and again during packaging.
4. Darwin build stages normalize every helper to a verified ad-hoc signature before issuing a receipt. Mach-O payload identity excludes only the bounded `LC_CODE_SIGNATURE` tail and deterministically normalizes its `__LINKEDIT` size fields; PE identity applies a strict no-overlay Authenticode certificate-table projection; ELF retains the complete raw digest. Platform signature verification remains mandatory and is not replaced by payload hashing.
5. Electron, Python, and plugin production paths do not resolve or execute data helpers directly. The Go-owned service supervisor and frozen native-component registry are the only execution authority. Development may select only `runtime/data-native/<platform>-<arch>` under explicit local-build authority; packaged execution remains unavailable until a release authority receipt is implemented and verified. No Electron/Python override or inherited helper path can regain execution authority.
6. Electron resource selection expands the builder target architecture. `afterPack`, the macOS post-sign/notarization hook, and the Windows artifact audit fail closed on a missing, stale, tampered, symlinked, unprobed, unsigned, or wrong-architecture helper or receipt. Windows/Linux x64 package entrypoints require target-native x64 hosts.
7. End-user packages contain binaries and receipts only; they do not contain Rust source or require a user-installed Rust toolchain.
8. Packaged Windows CPython/backend material is dormant migration input, not a second process authority. Its fixed archive, approved source tree, exact hash-locked wheel set, pruned runtime tree, and site-packages tree remain package-audited, but Electron main cannot execute them. Re-enabling requires a Go-owned supervisor with registry-bound tree hashes, suspended no-breakaway Job Object containment, bounded protocol/readiness, confirmed termination, and a strict desktop proxy; local source/interpreter overrides remain forbidden.
9. A local native build performs a read-only release preflight before creating an output directory, build lock, temporary directory, source session, or toolchain subprocess. A repository, Cargo executable, or Rust compiler writable by the invoking user is classified `toolchain_user_writable`; this is audit-only `local_provisional` evidence and blocks publication before effects. A future controlled coordinator must issue `CargoExecutionReceiptV1` and a process-confined, one-use `PublicationPermitV1`; the standalone publisher rejects caller JSON that claims eligibility or embeds a raw receipt.
10. Source snapshot create/verify and cleanup use distinct descriptor profiles. Verify and exact `discard` bind generation, canonical inventory, and canonical receipt SHA-256. `reconcile_discard` accepts no caller generation identity and may remove only an empty session, one clean current generation with no predecessor/transaction residue, or prove that the same open parent was already removed. It never upgrades a lost or failed create/verify/discard into successful build evidence. A same-name replacement or unknown residue is quarantined.
11. The Darwin descriptor-loaded launch gate uses per-function poison state and classifies invalid input, clean pre-resume rejection, cleanup ambiguity, post-resume ambiguity, poison, and reentrancy separately. File descriptors are closed exactly once; a post-resume output/drain/reap/rehash/marshalling failure invalidates that gate instance. A separately loaded function may be used only for explicit cleanup after independent proof that the old process tree is empty, never to retry a probe or recover publication eligibility. The gate remains `local_provisional`: same-UID addon mutation/SIGCONT interference, process-group escape, user-owned toolchains, and incomplete release coordinator authority continue to block a release claim.

## Persistence Startup Migration

1. Resolve Go data/durable roots and every separately owned security root, including Electron user data supplied through the desktop launch contract, to canonical, non-overlapping paths before construction. Phase zero performs no-create discovery of existing journal/retirement/control namespaces. The production CLI holds one composite OS coordination lease over shared ancestors and exclusive roots for the handler lifetime, and the leased constructor rejects root retargeting; the lease is not migration or signing authority and cannot create an authority namespace before the composite read-only fixed point.
2. Before legacy migration or directory creation, perform a deterministic two-pass scan of security-relevant durable/private state. Reject duplicate JSON keys, unsafe thread bindings, non-contiguous event sequences, authority-log framing damage, symlink/special-file substitution, unrecognized hardlinks, or a changing file/directory manifest. Directory traversal is paged at 256 entries, cancellable, bounded by 100,000 snapshot entries, 64 path components, 4 KiB paths, 64 MiB per managed file, and 2 GiB per staged generation; semantic plans are limited to 10,000 operations. The sealed baseline distinguishes absence, empty directories, regular files, mode, size, modification time, record count, and full SHA-256; it includes attachments and the MCP schema cache as managed startup inputs and binds the validated current-run configuration only by digest. This baseline is a prerequisite to, not a substitute for, the complete semantic inventory and journal.
3. Private-CAS crash recovery belongs to the host-authorized CAS owner. Existing authenticated transaction recovery and topology-derived no-create cleanup are an explicit pre-baseline recovery phase, not part of a new migration apply. After that phase settles, all owner roots are recaptured before any fresh plan is built. Before opening a new semantic journal, one topology-derived no-create pass may delete only an exact `.analytix-cas-create-<component>` directory that is private, single-device, identity-stable across complete repeated observations, strictly empty, and located at one of the fixed directory/shard creation slots. This pre-journal pass has no authority over a canonical final directory, a non-empty directory, a case alias, an unknown residue, a record temp, or any committed body. The authenticated active semantic journal is then recovered; only afterward may a fresh global read-only preflight classify empty canonical shard residue, recursively empty incomplete owner topology, and every composed CAS owner's store-specific residue before owner cleanup and the first generic baseline. This prevents a new owner cleanup from invalidating an older signed journal baseline while allowing a crash between staged-directory creation and no-replace installation to converge before journal traversal. A signed legacy journal may admit one otherwise rejected residue only through an exact canonical `remove_file` operation whose before state matches the captured file; it gains no general temp allowlist. Missing roots are not created during recovery, and a later-parent, later-shard, or later-owner failure causes zero earlier cleanup. The snapshot never interprets a hardlink or temporary filename as committed authority: any remaining unapproved private-authority temp/hardlink fails closed. Planning copies use a fixed 1 MiB streaming buffer and a host-private persistent startup-authority namespace created only after the composite fixed point, never the shared OS temporary directory. The remaining full-tree-copy path is transitional and may not satisfy P1 closure until private/attachment bodies are replaced by a store-aware lazy-COW or touched-path plan.
4. Build and simulate the complete committed accepted-final event reconciliation inventory without writes. Unknown/uncommitted markers, unmanifested final events, non-prefix gaps, or any invalid projected replay abort startup before the first repair append. Repairable append failure remains an idempotent durable-outbox prefix for the next restart.
5. Normalize lease keys for case-insensitive volumes so case aliases cannot create a second writer, and require both the CLI and the `analytix_prod` embedded root factory to own a composite lease for the handler lifetime.
6. New accepted-final event suffixes are validated and sequenced as one manifest, durably appended by sibling-temp copy, file fsync, target-native atomic replacement, and the applicable directory/write-through barrier, then exposed to SSE only after the complete bundle commits. A post-replacement barrier error is tracked as committed-but-unpublished and read back before sequence allocation; orphaned pre-replacement temp files fail closed. Partial prefixes remain accepted only as a legacy crash-repair input.
7. Durable inventory/get/list APIs never trigger legacy import or source deletion. Legacy roots are visible only to the sealed startup migration planner; data appearing after construction remains quarantined until a later complete restart plan validates and journals it.
8. Startup control artifacts have independent limits: journal 8 MiB, planning marker 64 KiB, retirement tombstone 64 KiB, JSON depth 64, one million tokens, and 4 KiB strings. Current journal identity is schema/domain V4 with canonical full Unix dev/inode or Windows volume/128-bit FileID. An authenticated V3 journal migrates in place on Unix; Windows returns a typed full-FileID blocker without mutation. A missing-final authenticated V3 prepare temp follows the same platform policy and validates the complete rollback frontier before retirement.
9. Retirement schema/domain V1 is authenticated before migration classification. Unix proves the legacy dev/inode identity, V3 journal frontier, residue digest, and current managed state and may consume the signed deletion authority without rewriting the retired V3 journal. Windows cannot recover a complete 128-bit FileID from the legacy record and returns `semantic_retirement_v1_windows_full_file_id_required` without rewriting or deleting. Forged V1 material is an integrity error, not a migration blocker.
10. Planning, current-journal, retired-journal, authority-temp, per-CAS-root, cross-owner, and private-tree recovery use complete preflight before mutation. Later-page, later-shard, or later-owner unknown, special, hardlinked, over-depth, over-width, oversized, or identity-changed residue causes zero earlier cleanup. Directory inventories are reopened independently so repeated verification cannot share a consumed directory cursor. The CLI installs its signal context before preparation; cancellation propagates through recover, snapshot, simulation, apply, readback, and activation, and cannot publish a listener/readiness line after cancellation.
11. Legacy attachment records whose id is derived only from blob hash, whose scope is global/workspace/unknown, or which lack a valid `AttachmentOwnerRecordV1` are quarantined as non-executable. Migration must not infer a thread, case, epoch, snapshot, or use receipt from their path or legacy scope lists. Users re-upload the source into an existing thread to create a new owner. New uploads use private-CAS intent/disposition recovery without granting authority to legacy ownerless files. A later blob-layout migration may deduplicate raw blobs only after complete owner/use/upload inventories and crash recovery validate; it cannot merge legacy metadata into a new owner. Caller-reported source OS paths are untrusted private transport hints, not evidence or display metadata; new desktop uploads do not send them to Go, and public attachment contracts reject both paths and raw blob hashes. The older accepted path-propagation requirement remains only for separately typed, host-verified generated artifacts. Attachment preview/save/open migrates to attachment-id host actions; rollback may disable those actions but may not restore public source paths or filename-based merging with generated artifacts.
12. Before publishing a restart terminal boundary, the host completely preflights every active or pending durable ExecutionGrant in that stale turn. Duplicate/colliding call identities, malformed call authority, an unrecognized result, or an over-limit inventory causes zero reconciliation writes. Each valid orphan is then closed by one fixed metadata-only failed result, read back as settled, and never resumed, re-executed, converted into evidence, or emitted as a tool event. Repeated restart recovery is idempotent.
13. Checkpoint, CAS-create, journal, orphan, and owner recovery that can mutate managed state runs only in the authenticated pre-baseline recovery phase. A later semantic-plan failure can therefore prove zero mutation by the new migration transaction. Production startup must not capture a candidate baseline, mutate it through checkpoint recovery, and then call the recaptured state evidence that the earlier mutation never occurred.
- Do not edit historical reports to fabricate missing provenance.

## Compatibility And Failure

- General non-case chat remains available while the case gate rolls out.
- If migration cannot verify the context, source, registry, or snapshot, high-risk answers/reports remain boundary-only.
- Migration writes are atomic/idempotent and tested across restart. Partial migration never enables publication.
