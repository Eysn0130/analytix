# 原生文档标注与对话修改

Status: Reference。2026-09-14 用户对本轮交付的明确修正及有界 GitHub 研究。
当前实现以源码和候选验证为准，本页不构成验收或分发准入。

## 本轮目标修正

用户明确要求：复杂手动 Office 功能不做；支持在原生内容上标注，
把位置和上下文交给主对话，通过沟通让 AI 修改。
该修正覆盖早先附件中手动字体、字号、段落、公式编辑和复杂撤销重做的目标。
保留对象 Tabs、工作区内文件浏览、稳定主会话、三格式原生预览和安全边界。

交互为：标注 → 选中原生文本、单元格或页内对象 → 添加备注 → 加入对话。
加入引用不自动发送，也不覆盖主输入框。用户发出修改要求后产生提案，
接受后应用到工作副本并自动提交；只有 Core 持久化回执确认才显示已更新。
工具条保留“标注”，成功修改后显示“撤销”，文件操作合并为“打开”下拉
（用默认应用打开、在文件夹中显示、浏览工作区文件）；不提供常驻保存或导出按钮。
提案以红删绿增展示前后文本，属于应用提案对比，不宣称 DOCX 原生修订。
撤销只恢复本次 AI 修改之前的完整文件，使用当前修订 CAS，不能覆盖外部变化；
未知结果查询同一操作，重载前再次读取当前文件，失败时保留可恢复状态。
原生画布不提供手动编辑入口；内部受控修改能力不等于用户编辑模式。
范围、多对象及不完整选区可以讨论，不能假装具有精确写入目标。
现有框架与 Provider/Privacy Layer、Core scope、提案和保存权威继续复用。

## 验证边界

手动格式、复杂撤销重做不再是本轮验收项。
仍必须验证标注不串对象、不覆盖输入、不自动发送，原生交互不手动修改内容，
提案只作用于有效绑定范围，保存/重开准确，并保持宏禁止和 source-experiment 分发边界。
旧候选的复杂格式测试仅为历史证据，不替代当前收缩后的候选验收。
