# 特定双方资金往来核验

把特定双方转账事实写成公安经侦小研判材料，而不是工具卡、统计说明或
`funds_investigate` 摘要。普通案件用户不应看到 skill、MCP、SQL、专项资金核算、
case_id、workflow、support 字段、JSON、本地路径或工程词。

先读共享边界：[focused-skill-shared](../analytix-fund-analysis/references/focused-skill-shared.md)。
金额差异、重复/换卡、逐笔证据表和下游承接读法见
[amount-reconciliation](references/amount-reconciliation.md)。成稿口吻、禁词和
非模板化深度门见 [investigative-writing](references/investigative-writing.md)。

## Use when

- 用户问 `A 转给 B 多少钱`、`A 给 B 打了多少`、`A 和 B 往来多少`。
- 用户挑战金额、笔数、日期、账户、方向、成功状态、手续费、本金、重复/换卡、
  同一交易事实或原明细/复核后金额差异。
- 排行、quick fact、自然语言入口事实卡或报告段落给出两方候选金额，需要最终复核成稿。

## Not for / Do Not Use

- 普通 Top/ranking 或低风险单点数量，交给 `quick-fact`。
- 完整主体/账户画像，交给 `subject-dossier` 或 `account-dossier`。
- 金额已回答后的多层去向追踪，交给 `fund-tracing` 或 `graph-visualization`。
- 正式报告、附件或图表交付，交给 `report-builder` / `visual-evidence`。

## Workflow

1. 内部先界定付款方、收款方、方向、时间范围、账户范围、对手方粒度、交易状态和争议点。
2. 默认用当前案件语义事实工具取得最小充分事实，首选 `investigate_pair_amount`。
   `rank_counterparties`、`funds_investigate`、数据质量与口径复核和 workbench 只能作定位、
   交叉验证或缺口补算，不能替代最终金额判断。
3. 同时核对原明细金额/笔数、复核后有效金额/笔数、已确认重复记录、暂不能认定金额、
   起止时间、付款账户、收款账户、交易状态、备注/类型线索和当前案件内已见承接/分流。
4. 交易号为空、`查无信息`、`unknown`、`无`、`null`、重复占位或非唯一时，不能单独做去重键；
   有效交易号也必须结合时间、金额、方向、余额、对手、摘要/类型和状态判断。
5. 这不是 MCP-only。语义事实缺失、冲突、被用户挑战，或用户明确要求自定义统计/SQL/notebook/可回放核算时，
   转入 `case-workbench`：当前案件、只读、清洗表/analysis 索引、限行、purpose、
   核验状态和核验意见。不用 shell、目录搜索、本地 DuckDB 猜测、旧报告、旧截图、
   历史会话或 fixture 作为当前案件金额事实来源。
6. 首次回答取得可核验金额、笔数、期间和交易候选后停止同题工具链；不要再打开画像、
   图谱、全案或报告 lane 来扩写普通 `A 转 B 多少钱`。

## Output Contract

自然问句默认结论先行，首段直接回答金额、期间、笔数和账户范围，例如：

```text
经已调取流水复核，YYYY年MM月DD日至YYYY年MM月DD日期间，A 名下/相关付款账户
（列明账号）向 B 名下/相关收款账户（列明账号）转账 N 笔，复核后有效金额 X 元。
```

随后写清：

- `金额核对表`：金额类别、笔数、金额、使用边界、核验意见。
- `案件意义`：该两方转账对资金承接、交易背景、关系核验或后续穿透的意义；必须放在明细长表之前。除非具备支持利益输送具体主张的独立权威来源组合和人工复核，不得使用“利益输送”表述。
- `当前不能认定`：不能证明为新增转账、实际控制、用途或下游去向的事项；必须放在明细长表之前。
- `重点交易表`：时间、付款账户、收款账户、金额、摘要/类型、核验意见；小表不要折叠成
  `其余 N 笔`、`小额合计` 或 `多账户`。
- `异常特征`：时间集中、账户变化、重复/同事实风险、交易类型/备注线索。
- 复核后有效交易 20 笔以内时必须逐笔列出；若当前案件已有收款侧已见承接/分流，
  不要把已在案事实写成待调取事项。
- 结尾必须给出下一步核查建议，至少覆盖回单、余额承接、开户/控制、用途或产品/KYC/订单材料。
  普通问答可使用同义公安材料标题；正式材料、附件或金额质疑场景优先使用 `下一步核查建议`，
  不得降格成只列动词短句。

金额挑战、自定义范围或复核后有效追问必须写清 `本次依据`、`统计范围`、`来源边界`
和 `当前不能认定`，并解释竞争金额为什么不能相加、取最大或静默替代。

金额质疑类追问，例如“为什么不是某个更高金额”“为什么和去重金额不同”，不得只解释公式。
即使同一线程上一轮已经取得两方事实，最终可见回答也必须写清 `本次依据`、`已有流水支持`、
`核验意见` 和 `下一步核查建议`；事实不足或用户继续质疑时允许重新调用双方资金往来事实工具或
当前案件只读专项资金核算。发送前从已核事实中逐项保留精确数：复核后有效金额/笔数、初筛明细
金额/笔数、用户质疑的竞争金额、已确认重复记录金额/笔数、有效集中转账金额。竞争金额必须
写成 `#,###.00 元（####.## 万元）` 形式，并明确不能作为新增转账金额；下一步核查至少覆盖
集中交易银行回单、付款账号换卡/补卡记录、收款账号后续去向和用途材料。
金额质疑追问首句必须先写清已有流水支持的复核后有效金额和笔数；
在这个有效金额出现前，不要先写竞争金额、集中交易金额或重复金额，避免把线索金额误读为
最终金额。随后覆盖 `本次依据`、`金额核对`、`核验意见`、`暂不能认定`、
`下一步核查建议` 等证据义务；普通问答可用自然段或同义专业标题承接，正式材料或金额质疑成稿
应保留这些栏目语义。如果用户用中文大写/万位说法提出竞争金额，必须把事实包或问题中的
竞争金额转成阿拉伯数字千分位加 `.00 元` 的写法，并在正文显式出现一次。

`正在核验当前案件事实。`

## Completion Gate

只有复核后金额、笔数、期间、账户范围、差异解释、重点交易表、异常特征、案件意义、
当前不能认定事项和补证动作都具备，才可成稿。已在案承接/分流事实必须先写成事实，
不能塞进“下一步再查”。输出不外露工程词、内部字段、工具名、JSON、skill 名或固定工具卡标题。
