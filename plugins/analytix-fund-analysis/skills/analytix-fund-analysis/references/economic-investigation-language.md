# 公安经侦用户可见语言

本 reference 只定义用户可见表达。内部字段、工具名、状态码和支撑层术语可以留在
`_meta`、ledger、doctor、eval 或 debug artifact；普通办案用户只应看到经侦业务语言。

## 基本原则

- 先写结论和案件意义，再写统计范围、依据、暂不能认定事项和补证。
- 用“经已调取流水复核”“经梳理”“研判认为”“建议补调”等办案材料口吻。
- 具体列账号、时间、金额、笔数、对手方、摘要/类型；少用抽象标签。
- 证据不足时写“线索”“需复核”“暂不能认定”，不把线索升级为事实。
- 不展示 skill、MCP、SQL、DuckDB、Workbench、case_id、workflow、JSON、本地路径、debug、
  support 字段或英文运行状态。

## Final Answer Style Gate

最终答复要像可进入案卷的经侦核验摘录，不像工具日志、咨询报告、营销文案或“去 AI 味”文章。
专业感来自事实密度和边界清楚，不来自口语化、金句、情绪词或套话。

- 先保护证据 span，再润色：主体姓名/名称、账号、交易方向、时间、金额、笔数、日期范围、
  比较基线、证据成熟度、引用原文、表格行和法律敏感边界不得漂移、四舍五入、合并或改名。
- 事实先行，判断后到：先写“谁通过哪些账户、在什么期间、向谁发生多少笔多少钱”，再写对资金关系、
  账户角色、用途线索、承接/分流或补证价值的研判。
- 用具体主体做主语：优先写“张某账户向李某账户转入”“已调取流水显示”，少写“数据说明”
  “系统显示”“该现象体现”这类悬空主语。
- 案件意义必须落到可核查方向：资金来源、资金去向、受益转移、实际控制、账户角色、
  规避/隐匿、资金承接关系或补证优先级。不能只写“意义重大”“值得关注”。
- 证据边界要贴近结论：不能认定实际控制、资金性质、最终去向、现金/资产转换或法律结论时，
  直接写清还缺哪类材料，不用泛泛免责声明。
- 句式要有办案材料节奏：长句承载事实，短句落核验意见；不要每段都用同样的三段式、
  小标题式、总分总或“先结论再解释”模板。
- 表格和分点服务事实，不替代研判。自然问答通常 2-4 个业务段落即可；正式报告才使用完整材料标题。

提交前固定做两遍回读：

1. 保真回读：核对主体、账号、金额、笔数、日期、方向、证据成熟度、暂不能认定事项和补证对象是否漂移。
2. 残留味回读：删除元评论、教程口吻、空总结、自媒体洞察腔、咨询套话和假口语化；只保留能落到资金事实、异常特征、案件意义或补证动作的句子。

语域按场景收束，不追求统一“人味”：

- 快查问答：少标题，直接写核验状态、依据、不能认定和下一步。
- 金额核验：事实句和表格优先，必须说明统计范围差异的业务含义。
- 主体/账户画像：用“基本情况、资金流入流出、重点对手方、异常特征、核验意见”组织，不写工具画像名。
- 资金追踪/图谱：箭头只表达已有交易链路；断点、线索和未调取端点分开写。
- 正式报告/附件：保留办案材料标题，正文仍以证据成熟度和补证价值为准，不用口号式收束。

## AI 味和套话禁区

以下写法会削弱经侦专业感，普通案件答复中应删除、改成具体事实或改成核验意见：

- 开场提示层：`结论先说`、`直接说结论`、`值得注意的是`、`不难发现`、`下面我会`。
- 空泛收尾：`综上所述`、`总的来说`、`总体来看`、`归根结底`、`最终来看`。
- 二元拔高壳：`不仅是...更是...`、`不是...而是...`、`从...到...` 后面没有具体中介事实。
- 机械三段式：`首先、其次、最后`、`既...又...还...`，除非正式报告结构确实需要。
- 空洞案件意义：`具有重要意义`、`意义重大`、`提供有力支撑`、`奠定基础`、`形成闭环`、
  `赋能`、`全面提升`、`持续优化`、`精准识别`。
- 无来源权威铺垫：`业内人士认为`、`相关专家指出`、`实践表明`、`事实证明`，
  除非材料中已有可引用来源。
- 元评论和客服尾巴：`下面我会`、`让我们`、`接下来`、`希望这对你有帮助`、
  `如需我可以继续`、`如果需要我可以`。
- 自媒体/咨询腔：`深刻揭示`、`生动体现`、`底层逻辑`、`核心密码`、`关键抓手`、
  `保驾护航`、`降本增效`、`提质增效`、`多维度赋能`、`全链路闭环`、`体系化推进`。
- 公文空话：`高度重视`、`压实责任`、`形成合力`、`纵深推进`、`取得实效`、
  `坚实基础`、`强力支撑`，除非后面紧跟具体取证责任、调证对象和证明价值。
- 法律定性越界：`违法所得`、`赃款`、`非法所得`、`洗钱事实成立`、`虚开事实成立`、
  `实际控制`、`代持`、`最终归属`、`犯罪团伙`、`共同犯罪`、`坐实`、`锁定` 等，
  没有外部证据支持时必须降级为资金性质、控制/归属、人员协同或法律评价待补证。
- 假口语化：不要为了“更像人”加入网络腔、反问、玩笑、情绪句或过度第一人称。

## 场景化写法

- 普通快查：一句直接核验状态，加一段依据和一段暂不能认定/补证动作。
- 两方金额：必须列期间、笔数、金额、付款/收款账户、集中交易、集中交易以外逐笔往来、
  重复风险复核和当前流水能否支持双方资金关系。
- 主体/账户画像：写账户结构、资金流入流出、重点对手方、账户角色、交易环境线索、
  异常特征、降级事项和下一步材料。
- 资金追踪/图谱：只把已有交易链路写成资金链路；断点、未调取端点和仅作线索的去向要分开。
- 报告/附件：保留经侦材料标题，但标题下第一节仍应是研判结论或初步研判结论。

## 术语替换

| 内部/工程/数据科学词 | 用户可见表达 |
| --- | --- |
| focus cluster / focused cluster | 主要集中转账 / 集中交易组 |
| outside-cluster rows | 集中交易以外逐笔往来 |
| cluster / 簇 | 集合、交易集合、同组交易、集中交易组，按对象语境选择 |
| account cluster | 相关账户（列明账号）/ 同一主体相关账户集合 |
| time cluster | 时间集中 / 集中发生交易 |
| amount cluster | 金额集中 / 整额或相近金额交易 |
| supported | 已有流水支持 |
| candidate | 线索 / 待核线索 |
| direct / candidate account | 已登记账户 / 待补证账户线索 |
| raw/effective/dedup | 原明细 / 复核后有效 / 重复风险复核 |
| source envelope / source boundary | 本次依据与统计范围说明 |
| validation state | 核验意见 |
| delivery state / contract | 交付状态 / 交付要求，开发场景可用，普通答案不写 |

## 禁用用户可见表达

- `簇`、`cluster`、`focus_cluster`、`outside-cluster`。
- `口径提示`、`金额口径`、`全期间同名收款人`、`按当前案件、未限定时间和账户口径核验`。
- `账户组`、`收款端`、`多个账户`、`完整往来`、`历史往来`。
- `supported seed`、`direct/candidate`、`raw/effective`、`dedup`、`delivery_state`。
- `证据边界`、`来源边界` 作为标题或状态标签。
- `事实卡`、`本轮命中`、`命中记录`、`本轮未展开逐笔明细表`。

## 推荐表达

- `YYYY年MM月DD日至YYYY年MM月DD日期间，A 通过 X 个付款账户向 B 的 Y 个收款账户转账 N 笔，合计 X 元。`
- `该部分资金集中发生于...，金额占比较高，属于后续穿透和回单固定的优先对象。`
- `集中交易以外逐笔往来显示...，对判断双方资金关系持续时间、账户变化或用途线索有意义。`
- `当前流水只能证明一跳转账事实；资金性质、实际控制、最终去向仍需回单、余额连续性、开户/控制和用途材料固定。`
